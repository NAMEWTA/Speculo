# 维护 Speculo

Speculo 为现有 AI 宿主提供工作方法与项目知识，不实现另一个 Agent 编排器。

## 找到真实来源

- 先看本次任务涉及的源文件、调用方和已有测试；不要求每次通读仓库。
- `src/` 是 CLI，`template/` 是随项目安装的工作流，`skills-hub/` 是可单独安装的实用技能。
- 本目录只指导维护者。安装路径与分发行为以当前代码为准，使用说明见仓库 README。
- 尊重已有用户文件和并行修改。持久资料写在用户项目中，不写入技能安装目录。

## 写最少的有效指导

- `SKILL.md` 用 `name` 与 `description` 描述能力和准确触发条件；只有实际需要才增加其他元数据。
- 正文说明目标、必要的项目知识、真实操作边界和完成结果，让模型自行选择实现步骤。
- 一份文件足够就不拆。技术资料太长或工具确有复用价值时才放入直接可达的参考文件或脚本。
- 引用已有代码、设计、文档或部署配置，避免复制同一事实。给引用说明用途，不要求全部预读。
- 不为提示词创建状态机、固定角色、轮次、派单协议、文档 schema 或空模板。
- 需求、UI 原型、spec、实施与部署可连续推进；任务不需要的环节直接省略。
- 用户已给出的目标、授权和限制继续有效，只为确实影响范围或不可逆效果的缺口询问。

## 保留需要复用的东西

工作记录帮助下一次继续；长期知识保存仍有效的决策、项目事实、故障经验与设计。优先更新已有文件。
设计可以是原型代码、组件示例或图片，不要求额外抄写成 Markdown。具体部署命令和恢复方式可复用，凭据只保留安全引用。

## 检查实际结果

按改动检查技能发现、链接、打包和安装行为；修改安装器时验证用户文件不会丢失。
保留有实际用途的解析器、清理工具和 API 辅助脚本；不要把“精简”误作删除执行能力。
运行相关检查，修复本次引入的问题。报告真实结果与未验证范围，不以标题齐全代替可用性。

改编材料保留来源和许可证；原创综合与复制内容分开说明。来源总表见 `THIRD-PARTY-NOTICES.md`，设计参考见 `docs/research.md`。
