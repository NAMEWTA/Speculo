# Authoring quality

本模型将 `template/skills/writing-great-skills/SKILL.md` 的方法用于 Speculo 资产。目标是让 Agent 每次遵循同一可检查过程，而不是追求字面相同的输出。

## 预测性

每个资产都要回答四个问题：何时进入、先读什么、按什么顺序行动、什么证据表示完成。缺少其中任何一项都会扩大随机性。

## 主导词

为每个 skill、command 或 work 选择一个模型已熟悉的紧凑概念，放在 description 和核心步骤中。一个主导词只对应一个职责分支；同义触发词不重复堆叠。

## 信息层级

1. `SKILL.md` 或入口文件保留每次运行都需要的步骤。
2. 某分支才需要的规则放在直接 reference 中，并在触发该分支的步骤就近指向。
3. 可机械执行的枚举、编译、索引或验证放入 script。
4. 跨技能共享的项目事实只放 `_shared/`。

指针必须说明“何时读取、读取后用于完成哪一步”，只列文件名不是有效渐进披露。

## 完成标准

每个步骤以可观察条件结束：

- 能区分完成和未完成；
- 关键步骤要求穷尽所有目标，而不是给出样例；
- 需要运行命令时记录命令、退出码和关键输出；
- 无法完成时列出具体阻塞、受影响路径和未验证假设。

## 单一事实源

同一规则只维护一次。入口文件引用 contract，不复制 contract；contract 引用项目模型，不重复目录和所有权。生成产物（AUTO-INDEX、canonical）只由源重建，不手工维护第二份规则。

## 修剪

逐句执行：

1. 这句是否仍与资产职责相关？
2. 删除它是否会改变 Agent 的行为？
3. 同一含义是否已在更权威位置出现？
4. 它是否只服务某个分支，应当下沉？

删除不相关、无效、重复、过时和被更具体规则取代的句子。优先描述目标行为；只有安全或所有权边界保留明确禁令，并同时给出正确替代动作。

## 结构选择

- 仅当能力有独立触发分支或多个调用方需要独立到达时拆成 skill。
- 仅当可见后续步骤持续诱发过早完成时按顺序拆分。
- 内容很长但每次都需要时保留在入口；长度本身不是下沉理由。
- 内容很短但只属于少数分支时下沉。

## 完成门

资产只有在以下条件全部成立时完成：

- description 覆盖每个真实调用分支，且无重复触发词；
- 每个步骤有检查标准，关键步骤穷尽；
- 每个外部 reference 都有触发指针；
- 每条共享规则只有一个权威位置；
- 无失效路径、旧 id、旧 namespace 或手工维护的生成区块；
- 对至少一个正常场景和一个失败场景执行了验证。
