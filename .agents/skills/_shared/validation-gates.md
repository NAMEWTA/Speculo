# 按风险选择验证

按实际变化选择下面的检查；组合变更取相关检查的并集。同一结果可复用，只有新修改、失败或未决疑点才扩大或重跑。不要求逐项解释未触发的分支。

| 改动 | 必要验证 |
|---|---|
| 文字、事实或示例修正 | 核对直接事实源、涉及的链接、格式与示例；无行为变化时不另写正常/失败测试 |
| Skill/Command/Work 入口、路由、权限或完成条件 | 相关元数据、引用闭包、owner 与正常/近邻不触发/缺少授权场景；失败只阻塞受影响分支 |
| 状态、写入、安装、提交或事务合同 | 相关 schema 与 disposable fixtures，覆盖冲突、漂移、部分失败、恢复和未授权零副作用 |
| 生成、重命名、移动或删除资产 | 迁移调用方和源映射，重建受影响输出，二次生成无差异；保留的旧名命中须有历史或兼容依据 |
| 分发资产或其引用/生成依赖 | 项目 `pnpm validate-assets`；新增分发 Skill 同时确认 `pnpm validate-skills` |
| 发布或包布局变化 | 项目完整检查及适用的 bin、package、generated 验证；发布授权另行核对 |

## 结构与语义

只检查受影响资产：frontmatter/JSON 可解析，ID、目录、manifest 与 AUTO-INDEX 一致；静态引用可达，动态路径有变量、owner 和生成时机。入口的触发与退出可区分，必要资料在使用前读取，分支 reference 不成为无条件前置阅读。

每个写集有唯一 owner。记忆写入使用原 gateway，检查 pending transaction、lock 和 recovery evidence；其他任务的冲突只阻塞重叠写集。同一具体批准由入口复用，内容漂移时重新核对。

用户提供参考内容时保留其来源、许可、独有证据和明确要求；适配与获批重构的行为变化单列，不能靠减少交付或省略必要验证通过检查。

## 完成与证据

所有本次验收条件有结果，未决项没有被标为完成；记录实际命令、退出码、失败范围及恢复入口。静态文本断言不替代真实工具/宿主行为验证。

跨项目维护者包没有项目校验命令时，可使用：

```bash
node .agents/skills/speculo-write-workflows/scripts/validate-speculo-assets.mjs .
```

项目命令已包含此检查时不重复运行。保留结构、路径和授权不变量，避免把重复警告或固定措辞写成测试契约。

SpecDev 生命周期改造同时证明无安装直接 Work、唯一 Outcome、轻量/复杂入口、原 owner 完成/取消、A 先维护后移动、来源移动后可解析、当前协议拒绝与未知/历史原件保全。普通新 writer 旧镜像命中必须清零；保留旧名须分类为历史原件、拒绝测试或其他领域。结构验证不认证真实用户授权，浏览器/宿主观察与夹具分开报告。
