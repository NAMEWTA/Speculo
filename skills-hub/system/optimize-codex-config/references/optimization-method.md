# AI CLI 配置优化方法

## 从需求与证据出发

优化不是下载一份最大化配置。先定义问题（初始化、上下文浪费、成本、等待、状态缺失、外部流量或明确故障），记录原状态，再选择最小可验证改变。用户提供的模型、供应商和权限是需要保留的事实，不是通用默认。

自动策略仅处理隐私和状态栏；其他优化用下面的诊断方法形成单独确认包：当前值与来源、问题证据、目标值、质量／成本／安全代价、逐文件脱敏 diff、版本与作用域证据、备份、验证和回滚。不能修改任意 plan JSON 让自动引擎代为执行超出 allowlist 的更改。

## 模型、推理与上下文

从实际可用模型与本机能力选择，不固定模型名称。常规任务保留当前或适中 effort；难题只有质量收益值得等待与成本时才提高。计划模式与普通模式可能有独立设置，不机械同步。API 页面最大上下文不是 Codex 本机模型目录的替代品，不夸大 model_context_window。

先减掉重复、冲突、与当前任务无关的全局指令；把大参考资料按需加载。AGENTS.md / CLAUDE.md 保持短而可验证，把详细方法放对应 skill references。不要为了“完整”将全部技能正文、工具列表和历史每轮塞进上下文。

上下文占用、订阅窗口额度与费用分开。压缩阈值不是 HTTP body 上限；更早压缩可能增加压缩频率、成本并损失细节，不能承诺统一收益比例。长任务先制作可验证交接，再新会话；保留必要历史以支持恢复。

## 权限与工具

保持现有审批／沙箱与网络边界，不把 danger-full-access 或跳过审批作为性能优化。工具网络与模型 host 请求分开。TLS 校验、本地危险命令检查、文件恢复和安全 hooks 不能因为“外部遥测关闭”一起被关闭。

MCP 按任务安装和启用，不体检时启动全部服务。只读检查 command/path、配置来源和所有者；真实启动与 tool discovery 是另一个有副作用的授权步骤。工具按需加载应先确认模型／网关协议兼容，不能强制发送第三方不支持的 tool_reference。

Agent 并发由任务可并行性、供应商限制、内存和成本决定，不默认启用最大值。hooks 保留本地测试、格式化、安全检查；将上传、外部检测、自动下载和重型回调逐项分离。不同集成事件不能因名字相同而合并。

## 第三方工具取舍

| 候选 | 借鉴／可选用途 | 不默认采用的部分 |
|---|---|---|
| Codex 原生 TUI | 原生状态项目与限额语义 | 外挂额度客户端、终端画面抓取 |
| Claude HUD | 可选上下文／工具／Agent 可视化；当前 README 的隐私承诺仍须按固定版本核验 | 不把 README 当作所有版本的安全证明 |
| ccstatusline | 可选布局与组件 | 不整体启用有外部副作用的组件 |
| ccusage | 按需本地历史与成本分析 | 不把估算成本或 blocks 当真实订阅余额；运行器下载和离线参数分开 |
| CC Switch | 识别配置所有权与切换覆盖 | 不接管数据库、不默认健康检查 |
| Claude Code Router | 已有路由的边界理解 | 不为了优化而新增代理层 |
| rulesync | 公共意图与产品适配器分离 | 不机械互转两款 CLI 的配置 |
| Everything Claude Code | 模块化、按需加载与工作流验证 | 不默认整包安装 skills/hooks/自动化 |

第三方方案只作为可选研究，不由本 skill 自动安装或更新。最终默认仍是 Codex 原生状态栏＋Claude 小型本地 stdin 渲染器，最大限度减少依赖和额外凭据接触。
