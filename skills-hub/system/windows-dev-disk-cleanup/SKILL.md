# Windows 开发机磁盘清理

确认原生 Windows、目标卷、实际用户和请求范围。WSL 或远程 Linux 的结果不能替代宿主。只读盘点不删除、不卸载、不停进程；已有具名清理授权直接沿用。

## 找到真正占用空间的对象

按 [平台清理方法](references/windows-cleanup-workflow.md) 记录卷空间、相关大目录、应用与工具链。扫描不跟随 junction/reparse point，不为测量触发云占位文件下载。

硬链接、压缩、稀疏文件和 VHDX 会使逻辑大小与可释放物理空间不同；目录估算不能直接相加。先从症状和大目录缩小范围，避免重复全盘扫描。

保留一份普通清单即可：准确路径或产品 ID、用途、是否可重建、估计大小、处理决定和实际结果。扫描发现新对象不自动扩大删除范围。

## 按对象选择方法

| 对象 | 合适处理 |
| --- | --- |
| 可重建缓存 | 工具支持的 cache purge/store prune，保留配置、凭据和历史 |
| 托管应用 | 官方卸载器或包管理器，核对产品身份与共享依赖 |
| 重复工具链 | 先在新会话验证保留版本、shim 和项目 pin，再处理旧版本 |
| 项目生成数据 | 只处理指定项目的明确生成路径，保留源码与本地状态 |
| 下载与用户文件 | 按用户具体选择处理，说明删除是否可恢复 |
| 系统存储 / WSL / Docker 虚拟盘 | 单独判断数据、服务和恢复影响，不视为普通缓存 |

注册表清理不作为常规步骤。WinSxS/ResetBase、pagefile、WinRE、还原点、更新数据和虚拟盘压缩各有独立效果。不能直接删除或压缩活动 VHDX。

## 执行边界

使用字面路径和 `LiteralPath` 语义，拒绝空路径、卷根、意外重解析和身份变化。优先精确产品卸载与工具命令，不用通配删除代替对象判断。

保留承载当前 Agent、shell、编辑器或活动进程的运行时。替代工具链验证失败、文件锁定、系统 servicing 进行中或共享依赖不明时，保留受影响项并说明；不要强制解锁或关闭维护进程。

删除不可逆时，清单不是回滚机制。已有备份只证明相应内容可恢复，不能将其推广到未知用户数据或整个应用状态。

## 验收

按范围分批执行，测量卷真实可用空间变化，检查保留工具的路径与版本、相关项目和数据。卸载器退出成功后仍要核对程序、注册项与残留。

报告已完成、失败、保留、锁定及待重启项。不要自动重启；需要新会话才生效的 PATH 或 shim 变化，注明后续核验方式。
