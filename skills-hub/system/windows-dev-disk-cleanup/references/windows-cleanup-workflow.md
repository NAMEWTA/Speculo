# Windows 开发机清理工作流

用于大范围审计、交互式清理规划，或已授权执行。按这台机器裁剪清单；某个工具或路径不存在是结果，不是错误。

## 只读发现

提出清理方案之前，先抓一份初始快照：

- 固定卷的总空间和可用空间，尤其是 C: 以及开发/数据盘。
- 当前身份、管理员状态、活动进程、Windows servicing 是否正在进行、待重启标记。
- 休眠、pagefile、还原点、回收站、WSL 发行版/功能，以及其它相关的系统托管存储状态。
- 已装桌面应用：机器级/用户级，以及 32/64 位卸载注册；需要时再看 Appx 包和可选功能。
- PATH 以及工具相关环境变量，覆盖进程、用户、机器三个范围。
- 正在用的和重复的开发运行时：Volta/Node/npm/pnpm、uv/Python/pip/Conda、JDK/Java/Maven/Gradle、Rust/Cargo、.NET、WSL/Docker、IDE、CLI 及其包存储。
- 用户配置目录里的大目录、应用数据、包缓存、IDE 缓存、构建产物、下载、回收站、压缩包、虚拟机镜像、ISO、以及范围内各盘上的大型项目树。

注册表、Appx、功能、XML/JSON 配置和环境变量用结构化 API。体积扫描是只读的，但可能很贵；从已知高收益根目录开始，不要把同一个重解析点跟两遍，并对可能因硬链接或 junction 重叠的估计做标注。

## 给候选分类

问用户决定之前，先给每项分类：

| 类别 | 通常怎么处理 | 主要风险 |
|---|---|---|
| 可重建缓存 | 用所属工具清理 | 重新下载/重建索引的时间 |
| 托管应用 | 先走官方卸载 | 共享组件和用户数据 |
| 重复运行时 | 先验证要保留的版本，再拆闲置版本 | 弄坏正在用的工具 |
| 项目生成数据 | 只删精确的生成路径 | 把源码或本地状态误分类 |
| 用户/业务数据 | 除非被点名，否则保留 | 不可恢复的数据损失 |
| 系统托管存储 | 单独明确决定，并做管理员核实 | 启动、服务或回滚损坏 |
| 过期注册/残留 | 证明产品已不在之后才删 | 弄坏仍有效的安装 |

目录大不等于可以安全删除。要说明谁拥有它、能不能重建、支撑哪条工作流、以及必须留下什么。

## 清单合同

根目录清单至少包含：

```markdown
# Windows 磁盘清理清单

> 更新时间：YYYY-MM-DD
> 当前状态：只读排查 / 决策中 / 已授权执行 / 待重启收尾 / 已完成

## 基线
| 卷 | 总空间 | 可用空间 | 可用比例 |

## 已批准清理或卸载
| 编号 | 项目 | 决定 | 已知大小 | 精确边界 | 状态 |

## 明确保留
| 编号 | 项目 | 保留边界 |

## 待确认
| 编号 | 项目 | 风险/收益 | 问题 |

## 执行记录
| 时间 | 项目 | 方法 | 结果 | 实际空间变化/残留 |
```

候选编号跨批次保持稳定。每一批问简短问题：估计收益、后果、精确范围。先把已答行写入清单再继续。用户改边界时（例如从清理旧仓库改成保留整个包管理器目录），立刻把新规则用到后续全部工作；已经做完、无法撤回的动作如实记录，不要掩饰。

## 执行阶段

### 1. 建立替换项

- 尽可能在新进程里验证每一个要保留的运行时和包管理器。
- 确认要保留的 Java 和 Maven 设置解析到预期位置。
- Python 迁移：先安装并验证替换解释器/工具管理器，再拆除 Conda 或其它环境所有者。
- Volta：检查默认运行时和每一条要保留的包 pin。拆掉旧 Node 映像之前，先给要保留的 CLI 重新 pin。

### 2. 托管卸载

- 先关掉相关应用，核实精确进程后再停任何东西。
- 只有已知其支持的参数时，才用应用官方静默卸载器；否则记录为需要交互确认。
- MSI 必须针对已核实的精确产品代码。退出码 0 不够：之后还要验证注册项和程序路径是否已去掉。
- WSL：禁用功能前先盘点发行版。注销发行版会毁掉它的文件系统，必须单独明确批准。

### 3. 缓存和开发数据

- 优先用受支持的命令，例如包管理器的 cache purge 或 store prune。
- 仓库和配置与缓存分开处理。尤其是 `.m2/settings.xml`、Maven 本地仓库、npm/pnpm store、Cargo registry、IDE 历史、凭据、以及模型/会话目录，可以各自独立决定。
- `node_modules` 这类生成依赖，只对用户点名的项目删除，并保留源码管理元数据和源文件。

### 4. 已批准文件和回收站

- 已批准的下载、压缩包、视频、课程材料、部署包、项目产物，使用字面、完全解析后的路径。
- 确认删除是可恢复还是永久。只清空用户明确批准的盘的回收站，并且要在此前所有删除都复查过之后。

### 5. Windows 设置和残留

- 关闭休眠用 `powercfg /hibernate off`；永远不要手工删 `hiberfil.sys`。
- 可选功能通过受支持的 Windows 功能 API 改；未经批准不要自动重启。
- 先枚举还原点。若决定保留最新一点，不要用宽泛的 `vssadmin delete shadows`。
- 通过环境变量 API 改机器/用户 PATH，只删除精确的过期条目。
- 过期卸载键或安装器缓存：只有核实产品、安装目录和所属应用都不在之后才删。
- 避免组件存储清理、`ResetBase`、改 pagefile、删 WinRE、删 Windows Update 缓存，以及含糊的系统日志/临时文件清理，除非每一项都单独获批。

## 硬停

出现下列任一情况，停止改动并报告证据：

- 要保留的命令、仓库、应用或替换运行时验证失败。
- Windows Update、DISM、MSI、TrustedInstaller 或 TiWorker 正在改系统状态。只读功能查询可能短暂拉起服务进程；等一等，区分“查询带起来的空闲进程”和“真正在维护”，不要杀掉它。
- 卸载器报告共享组件、需要计划外交互、返回说不清的退出码，或留下所有权不明的状态。
- 精确目标扩到批准路径之外、经过意外的 junction 解析，或包含要保留应用的数据。
- 当前进程正在使用准备拆除的运行时或可执行文件。
- 管理员步骤缺少管理员权限。

## 最终验收

完成时记录并核实：

- 范围内每个卷的最终可用空间和实际增加量。
- 已拆除的程序路径、注册项、包条目、快捷方式、精确环境变量条目确实不在。
- 每条关键保留工具链的版本和路径。
- 受保护配置和仓库的完整性。
- 休眠/功能状态、还原点数量、服务进程状态、待重启工作。
- 有意残留、只能交互卸载的程序、被锁运行时，以及重启或新会话后必须做的精确动作。

不要因为卸载器返回成功，就把请求项报成完成。可观察的事后条件和更新后的清单才是完成标准。
