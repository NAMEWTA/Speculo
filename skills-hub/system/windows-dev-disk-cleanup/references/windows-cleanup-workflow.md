# Windows 开发机清理方法

从空间目标、实际卷和用户指定范围开始。批量清理可保留一份简短记录，写清选定对象、保留项、原始空间与结果；无需固定清单合同或每批重新确认已经授权的动作。

## 定位占用与归属

用 `Get-Volume` 查看实际卷，按证据检查大目录、应用、开发缓存或虚拟磁盘。只有相关时才深入卸载注册、Appx、可选功能、环境变量和系统托管空间，不为清一个项目先全量枚举整台电脑。

体积扫描不跟随未知 junction/reparse point，不读取云端占位文件触发下载。NTFS 硬链接、压缩、稀疏文件和共享组件使目录逻辑大小不等于可释放容量。Windows、WSL、Docker Desktop 的空间分别核对。

记录实际运行的工具版本和路径，区分进程、用户、机器级 PATH。发现多套 Node、Python、Java 或 CLI 时，先确认项目 pin、虚拟环境、服务和当前 Agent 依赖哪一套，再判断是否冗余。

## 分类后选择处理方法

| 对象 | 应查明的事实 | 可用方法 |
| --- | --- | --- |
| 构建产物与缓存 | 是否可重建、是否活动、离线恢复成本 | 所属工具清理或精确生成目录 |
| 托管应用 | 产品身份、共享组件、用户数据 | 官方卸载器或包管理器 |
| 重复运行时 | 项目 pin、路径顺序、替代版本是否可用 | 验证替代项后移除闲置版本 |
| 下载和用户资料 | 是否还有唯一副本、用户选定范围 | 字面精确路径，区分回收站与永久删除 |
| WSL/虚拟磁盘 | 发行版和磁盘归属、实际数据、运行状态 | 对应平台的导出、清理或压缩方法 |
| 系统托管空间 | 启动、恢复、服务和更新依赖 | Windows 支持的管理接口 |
| 失效注册项 | 产品与安装目录是否真的不存在 | 只处理已核实的残留条目 |

大目录不自动等于垃圾。Maven 本地仓库可能含未发布包；IDE 历史、凭据、模型和会话也不是普通缓存。保留配置和源码，例如 `.m2/settings.xml`、项目锁文件与版本管理信息。

## 运行时与应用

移除旧环境前，尽量在新进程验证要保留的工具。Java/Maven 核对配置实际解析位置；Python 区分解释器与 Conda/uv 等环境管理器；Volta 检查默认 runtime、项目 pin 和仍需使用的 CLI。

官方卸载器只有在已知支持参数时才静默运行。MSI 用已核实的产品代码；退出码成功之后还要检查程序、包/注册项和相关 PATH。需要重启或交互时保留真实未完成项，不把它计为卸载完毕。

环境变量使用对应 scope 的 API，仅删除精确过期条目。不要为了规整 PATH 覆盖用户其他配置，也不要终止当前会话依赖的运行时来完成清理。

## WSL 与 Docker Desktop

`wsl --list --verbose` 可帮助确认发行版和运行状态，但 VHDX 路径与所有权仍需核对。删除 Linux 内部文件不保证宿主 VHDX 同步缩小；压缩需要满足相应平台的停止、备份与工具要求。

注销 WSL 发行版会删除其文件系统，不能把它当作普通缓存清理。Docker 的 volume、bind mount 和虚拟磁盘也分别判断；不要删除 VHDX 文件来“释放 Docker 空间”。当前 Agent 所在环境或正在运行的服务不应被无意停止。

## 系统存储与文件删除

休眠调整使用 `powercfg /hibernate off` 等系统接口，说明休眠及相关行为变化；不要手工删 `hiberfil.sys`。可选功能、组件存储、pagefile、WinRE、还原点及更新缓存各有不同影响，只有任务确实涉及时才按对应管理方法处理。

系统正在由 Windows Update、DISM 或 MSI 维护时，不与它竞争写入或强杀服务。只读查询可能短暂启动服务，应辨别真实维护活动和空闲进程。

对选定文件使用完全解析的精确路径；意外 junction、共享数据或范围变化时暂停该对象。回收站清空是独立的数据移除效果，须在用户指定范围内；不要为了让空间数字立刻上升而扩大到所有卷。

## 验证与接续

比较目标卷前后可用空间，说明测量期间的并发变化。验证涉及的保留工具、配置、项目和服务仍可用，核对应用卸载与实际路径，不以卸载器的退出码替代结果。

说明被锁文件、需新会话/重启生效的配置、只能交互处理的应用及有意保留的数据。已有授权允许的独立项目继续完成；需要用户处理的缺口给出具体对象与下一步。删除效果不可恢复时如实表达，不能因有记录就称其可回滚。
