# 浏览器 DoH 与 WebRTC：不把开关当成路径证明

先确认浏览器版本、正在使用的 Profile、企业策略、扩展及已有代理。这里给出决策流程，不保证某版本菜单或扩展仍存在。用户只要求改 Clash 配置时，不自动改全部浏览器、账号同步或扩展。

## 安全 DNS / DoH 的两种合规路径

**集中到 Clash 内核 DNS：** 先证明系统 DNS 已被 TUN/本地 resolver 接管，再在批准的浏览器 Profile 中关闭自带 DoH，避免使用另一个未批准 resolver。此顺序很重要：系统 DNS 仍直连时先关闭 DoH，可能把原先加密的查询降为本地明文。

**保留浏览器 DoH：** 用户希望保留时，核对它的 resolver 是否获准，其 HTTPS 连接是否实际走预期代理，并处理 DoH endpoint 的启动解析和自动 fallback。能观察到这条路径就不能仅因“安全 DNS 开启”宣布泄漏；它也可能是通过代理的加密 DNS。浏览器直连另一个公共 DoH 虽然可能不向运营商暴露查询正文，仍违背严格指定 resolver/代理路径的目标。

浏览器的自动、增加保护、严格模式或系统 fallback 名称依版本而变。看实际配置、策略与连接，不凭菜单标签推断。53 劫持不会解密或自动接管 443 上所有 DoH；同样不覆盖 DoT/DoQ。HTTP CONNECT 可把域名交给代理，SOCKS 客户端则需核对本地解析与远端解析选择，不能笼统说 HTTP/SOCKS 一定先本地 DNS。

| 浏览器 | 应记录与核对 | 不应自动做的事 |
|---|---|---|
| Chrome / Edge | Profile、Secure DNS 模式、自定义模板、管理策略、代理路径及回退 | 批量覆盖偏好、在运行时改 JSON、强装扩展或假定特定 uBlock 版本可用 |
| Firefox | 当前 DoH 保护级别/上游、策略覆盖、SOCKS 远端解析选项（若使用 SOCKS） | 把未知 about:config 键和值写成适用于所有版本的修复脚本 |
| Brave | DoH 和现有 WebRTC IP handling policy，实际媒体连接 | 为防泄漏直接关闭所有音视频功能或覆盖用户策略 |

更改浏览器 UI/受支持策略后读回，重试同一应用登录页面与正常网站。需要重启浏览器时由用户保存工作后执行；不杀掉浏览器或覆盖正在写入的 Preferences。备份原选择及“原先没有配置”状态；托管策略不能通过改低层文件绕过。

## WebRTC 不必然泄漏，但需要单独验收

WebRTC 的 ICE/STUN/TURN 可能使用与 HTTPS 不同的 UDP 路径；显式 HTTP 代理不等于该路径也已接管。TUN 对 UDP 的实际覆盖、浏览器策略、mDNS host candidate 隐藏和网络条件都会影响结果，因此不能笼统断言所有现代浏览器一定暴露真实 IP。

区分网页观察到的 candidate：本地/私有地址或 mDNS 名、STUN 的 server-reflexive 公网地址、TURN 的 relay 地址。发现一个私有地址不等于运营商公网地址泄漏；只显示代理地址也不能证明 CLI、DNS 或后台进程的全局安全。网页获取媒体设备/内容的权限与 ICE 地址暴露不是同一个判断，不能用“没弹权限框”作为测量依据。

用户明确要求限制非代理 UDP 时，优先评估浏览器支持的 IP handling policy，结合代理 UDP 能力和会议软件测试。Firefox 的 `media.peerconnection.enabled=false` 会禁用 WebRTC 功能，属于有功能代价的选择，不是默认网络优化。用户引用的 uBlock/WebRTC 选项或 Brave 策略需本机确认；不安装来历不明的“防泄漏”扩展，也不宣称某扩展能控制所有应用 UDP。

不能代理又要求绝不直连的 UDP，应该在明确范围做阻断设计，而不是悄悄 DIRECT；可能影响会议、语音、游戏和 QUIC。别把临时 TCP 对照测试变成全局永久禁用 UDP。

## 检测与分享

用户提供的 ip.net.coffee 页面可作为自选的第三方测试，但本轮未读取其实现、隐私说明或准确性，不作为唯一验收。访问前说明它可见公网 IP、DNS 测试标识、浏览器特征及可能的 ICE candidate；不要上传账号凭据或 API key。

在改动前后用同一 Profile、同一网络、相近时间记录脱敏结果，并关联 TUN/代理连接。DNS resolver 地理位置并不一定等于业务节点地理位置。分享只保留目的是否匹配、地址类别、规则链是否经过代理与失败时间；不公开完整公网 IP、内部域或原始浏览器日志，除非用户确有需要并明确批准。
