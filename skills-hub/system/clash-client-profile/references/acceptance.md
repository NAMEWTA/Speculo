# 网络变更事务与验收

## 状态机

`OBSERVE → PLAN → SNAPSHOT → CORE_VALIDATE → APPLY_ONE_STAGE → READBACK → DEVICE_TEST → ACCEPT`

每一步都留结果；发生异常进入 `STOP → PRIVACY_CONTAINMENT → ROLLBACK → RECHECK`。没有自动应用脚本：本技能提供计划、检查和受支持的 GUI/系统操作流程，不伪造跨版本持久化接口。

### 修改前

记录实际主机、客户端/内核版本、当前 profile 标识、原模式、原代理/TUN/DNS、组的实际叶子、目标域和一组正常网站。使用同一入口做可重复的基线请求，不先把所有设置重置。基线已损坏就注明，没有“改前可用”的证据不能将所有故障归因于本次调整。

每轮使用独立私有目录，文件备份包含原字节、权限/所有者、哈希、不存在状态。备份可能含 secret，比最终报告敏感；不入 Git/共享网盘。原生 Windows 记录 ACL，POSIX 私有目录 0700/文件 0600；保留原代理状态供恢复，不将旧回滚覆盖。

`dns_guard plan` 的哈希对应读取的快照字节；真正写入前，还必须核对活动配置/管理层没有发生订阅刷新或用户并发修改。快照哈希不自动锁住活动 GUI。SQLite 要有一致性备份/WAL 处理；不删 WAL/SHM。看不懂配置版本就停在 GUI 方案。

### 分阶段，不一次性全改

| 阶段 | 变更 | 进入下一阶段的条件 |
|---|---|---|
| 1 | 修正具名目标规则和保护组，保留原网络路径 | 规则模式下真实请求命中正确规则和非 DIRECT 叶子 |
| 2 | 更新内核 DNS 上游、bootstrap 与策略 map | 完整候选由实际内核接受；导出读回，静态 audit 无已知阻断；上游真实查询可用 |
| 3 | 调整 TUN 接管/53 劫持，保留已工作的系统代理 | 真实系统解析和业务连接走预期路径；无路由递归/冲突 |
| 4 | 必要时改一个系统网络服务的 DNS/IPv6 | 已验证 listener/目的路由，原生 IPv4/IPv6、LAN/企业域均符合方案 |
| 5 | 在获准 Profile 调整浏览器 DoH/WebRTC | 登录、普通网页、授权的会议/媒体测试不出现意外退化 |
| 6 | 用户批准的重连/睡眠/切网/crash 演练 | 冷启动可用；保护流量按设计阻断而非直连，恢复路径可用 |

阶段顺序依据现场可以保守调整，但不能跳过依赖：例如系统 DNS 指向本地 listener 前要先验证 listener；关闭浏览器 DoH 前要先验证系统捕获。保留原 stack/MTU；没有相关失败证据不顺便调优。

候选 `-t -f` 命令仅作本机帮助支持时的语法入口，使用隔离目录和已准备的 provider/Geo 依赖。真实核心检查可能读取文件或下载依赖，不冒充纯离线检查。语法通过也不能证明实际路由；GUI 可能丢弃键、执行晚于 DNS 覆写的脚本、保留旧 map，必须导出最终生成配置再审阅。

### 停止与回滚触发

配置验证失败、GUI 丢键/覆盖、无解析/大量 SERVFAIL、目标落到 DIRECT、意外本地 DNS 外发、业务可用性退化、节点 bootstrap 循环、端口冲突、旧 fake IP 不再路由、用户变更冲突时停止后续阶段。HTTP 401/403 的来源需区分，不把每个拒绝都当作 DNS 故障。

先控制隐私风险：暂停本轮受保护应用的测试/请求，不杀其他用户进程。**如果旧配置本身会泄漏，回滚到它只是恢复旧状态，不是完成隐私目标**；不要为恢复“能上网”而静默直连。用户需在已说明的可用性/隐私冲突中决定临时路径。

按相反顺序恢复本轮具体字段、浏览器选项、网络服务和客户端配置；原本不存在的设置恢复为不存在，原 DHCP/静态状态分别处理。不要全盘导入旧系统配置覆盖新改动。DNS/路由切换可能留下旧连接/缓存；在授权范围只重试受影响请求、必要时刷新本层缓存，避免清掉所有会话。恢复后读回并实测，否则回滚状态仍未验证。

远程会话没有本地救援或维护窗口，不执行可能断开管理路径的 TUN/crash/firewall 演练。TUN 和 strict-route 不是跨平台 crash kill switch；防火墙隔离需要另有确切范围、代理服务访问、bootstrap 例外、DHCP/LAN/管理保留和测试，不自动写 pf/nftables/Windows 规则。

## 现场验收矩阵

每行都有 `未运行 / 已观察 / 失败 / 不适用（说明理由）`，不能用一个总 PASS 覆盖未测项。

| 项目 | 最低证据 | 不能作为替代的证据 |
|---|---|---|
| 原始/候选/实际配置 | profile、版本、三份摘要哈希及字段差异 | 编辑器里已保存 |
| 规则模式 | 活动内核 mode=rule，真实目标首条匹配与最终链；直连目标能完成真实地址查询 | 节点名称“美国” |
| 全局隐私模式 | 活动内核 mode=global，GLOBAL 当前叶子与一次真实连接链；AI 前置规则标记为不生效 | 规则文件已保存 |
| 按订阅 DNS 覆写 | 目标订阅的覆写开关为开，生成配置中的 resolver 列表与计划一致 | 只复制了 dns_config.yaml |
| 节点 bootstrap | 物理网卡源地址上的连通性和中性域名答案；明文例外单独标记 | 经 TUN 访问 853 成功 |
| 显式代理 | 同会话请求 + 本机实际监听 | 另一浏览器的 echo |
| 内核 DNS 上游 | 批准 resolver 的查询、连接链与响应 | 只填 `respect-rules`；TCP 握手或已上传但下载为 0 |
| 系统 UDP/TCP DNS | 原生解析 + 限定测试的接管/物理接口证据 | 显式 DoH probe 成功 |
| IPv6 | 原生 IPv6 地址连接和 DNS 传输得到接管或明确阻断 | AAAA 空响应/只测 IPv4 |
| 浏览器 DoH | 实际 resolver/路径/fallback 与所选方案一致 | 关闭“安全 DNS”字样 |
| WebRTC | ICE 地址类别/UDP 路径与媒体功能结果 | 普通 HTTPS 出口正确 |
| 冷启动/订阅刷新 | 节点、providers、resolver、规则重新加载后的实际请求 | 热缓存状态下可用 |
| 睡眠/切网/组故障 | 新连接仍命中预期链，服务恢复记录 | 旧连接没有断 |
| crash 隔离 | 用户批准窗口内受保护请求停止而不直连 | TUN 开关/配置项为 true |
| 回滚 | 原具体状态恢复 + 真实请求/隐私状态标记 | 写回备份文件 |
| 服务区域 | 实际失败消失或仍拒绝的脱敏响应 | DNS 与节点显示同国 |
| 基础可用性/性能 | 普通网站、LAN/企业域、登录回调、媒体对照 | 单个检测网站“成功” |

第三方泄漏页面可补充 resolver 出口观察，但不能确认所有应用的路径，也不能单凭国家判断是否走代理。失败时先对准一层取证，不在同一次迭代同时换节点、DNS、TUN 栈、MTU、IPv6 和浏览器策略。
