# 网络优化：在已验证的路径上测量

目标是保持预期代理/DNS 路径与业务可用性，不是最大化一项测速或套一组“最佳参数”。先确认无 DNS 启动循环、路由排除、规则 DIRECT、IPv6 绕出、TLS 错误或节点不可达，再讨论性能。

## 最小对照

同一主机、客户端版本、节点、网络与目标，各取若干次冷/热解析和请求。记录失败率、DNS 查询耗时、TCP 连接、TLS、首字节、总时长及样本数；中位数与较慢样本分开。缓存命中很快不代表上游路径正确。第三方站点、CDN 与服务端限流会干扰对照，不编造提升百分比。

`curl --write-out` 可在本机帮助支持下取请求分阶段时间；走 HTTP 代理时，curl 的本地 namelookup 阶段不一定包含代理远端解析耗时，不能直接标成“目标 DNS 延迟”。本技能 DoH wire probe 检查响应路径，没有自动输出可靠的网络基准分数。

## 一次只调整一个因素

| 现象 | 对照与检查 | 避免的默认动作 |
|---|---|---|
| DNS 超时、SERVFAIL | 先分节点 bootstrap 与业务 resolver；检查被客户端保留的 policy/fallback | 换成本地明文 DNS“救急”却继续称隐私通过 |
| 规则/TUN 下某服务不可达 | 首命中规则、真实叶子、fake-IP 映射、域名可见性、旧连接 | 为这一个服务永久改成 global。用户另行选择的隐私全局模式见 [DNS 工作流](dns-workflow.md) |
| 小请求可用、大上传卡住 | 同节点的分段传输、MTU/PMTUD、UDP/TCP、TLS/HTTP 对照 | 把 MTU 一律设为 9000/1500/某个网上数值 |
| QUIC/HTTP3 失败 | 先核对 UDP 支持；经授权仅对目标请求做 TCP/HTTP 版本对照 | 永久禁掉整机所有 UDP/QUIC |
| 开启代理后 DNS 变慢 | 上游经同代理的延迟/缓存/可用性，避免引导循环 | 为速度自动 race 一个未批准 resolver |
| TUN 栈不兼容 | 保留当前栈基线；按内核版本一次试一个兼容栈并回滚 | 按操作系统统一强填 gvisor/system/mixed |
| 接口切换后失效 | 出站接口选择、其他 VPN、原生 IPv6、残留路由与连接 | 强制重启网络或清空整个防火墙 |

本方案只对 DNS 默认不优先 H3，减少与 respect-rules 的组合变量；这不等于关闭应用 HTTP3。resolver 协议、缓存算法、TTL、并发、ECH/HTTPS 记录、ECS 与硬件 offload 不因“优化”默认更改。尤其不注入真实用户子网 ECS，不关闭证书校验。

优化验收同时满足：保护路径仍符合方案、主要工作流不退化、错误率不恶化、回滚可用。不能只拿一个 IP/DNS 检测页的地理显示作为网络优化指标。
