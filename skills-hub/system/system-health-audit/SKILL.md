# 系统健康与性能定位

围绕症状、发生时间和受影响的工作负载采样。先确认目标是用户本机、远端、WSL 还是容器；工具所在环境不能自动代表用户设备。

## 建立基线

复用已有证据，选择相关时间窗口。区分持续变慢、某个任务变慢、偶发卡顿和单纯磁盘空间不足；这些需要的证据不同。

本包 Python 3.10+ 工具离线、只读、不提权，不递归扫描、不调用包管理器。`SKILL_DIR` 是本文件目录：

```bash
python3 "$SKILL_DIR/scripts/system_audit.py"
python3 "$SKILL_DIR/scripts/system_audit.py" --path /path/on/target/volume
```

Windows 使用实际可用的 Python 或 `py -3`，路径按 shell 正确引用。输出描述当前环境与所选文件系统；CPU 数量和剩余空间不是性能评分。

## 把症状连到证据

需要深入时按 [平台采样](references/platforms.md) 选择相关工具：

- CPU：观察持续占用、单核限制和当时任务，不能仅凭一个瞬间读数判断。
- 内存：结合内存压力、交换活动和进程需求；缓存占用不自动等于泄漏。
- 磁盘：区分容量、inode、IO 等待和虚拟盘；目录逻辑大小不等于物理释放量。
- 工具链：确认实际入口、版本和工作目录，排除不同运行时或依赖路径导致的差异。
- 远程/容器：注明资源限制与采样环境，避免将其结果推广到宿主。

保留采样时间和工作负载，区分观察、原因假设与验证。默认不输出完整环境、进程秘密参数、凭据或大段无关日志。

## 从诊断到行动

仅审计时不清理、停止进程或修改设置。建议说明具体对象、为什么可能有效、影响与可观察结果；没有足够证据时给下一项区分实验。

空间清理可转到相应平台的清理方法，网络路径问题看 Clash 方法，编辑器工具发现看 VS Code 方法。相关技能不存在时直接给可执行建议，不依赖安装兄弟目录。

已经授权优化时仍按实际证据选择改动，避免一键调整 swap、驱动、服务、索引和虚拟盘。需要恢复的动作保留适用的回退入口。

交付症状与基线、最有证据的原因、建议或实际动作、未验证项。收益在可比工作负载下前后测量；仅做审计就报告审计结果，不声称已经提速。
