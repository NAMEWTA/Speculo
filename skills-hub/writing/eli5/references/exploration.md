# 深入理解与发现盲区

主动深挖先回答核心问题，再选择值得展开的分支。角度是选题帮助，不是每次输出配额。

## 找有价值的分支

从概念差异、隐含假设、关键机制、反例、真实应用、失败情形和证据强弱中寻找会改变判断的内容。结合先修和当前目标排序，避免把所有相关知识同时展开。

区分四种情况：尚未讲到的潜在问题、用户回答显示的误解、材料缺少的信息、已有证据支持的事实错误。用户未提及某概念只能说明尚未观察，不能判定他不会。

每个重点分支说明：遗漏什么、为什么正常例子容易遮住它、会影响什么结论、怎样通过推理或证据区分。工程主题可以设计最小实验，数学使用推导与反例，语言用语境对比；不将它们统一成工程故障清单。

## 从表面到机制

例如讨论 API 超时时，不能只说“重试即可”。要区分请求未发送、服务器未处理、处理完成但回复丢失；再看接口是否幂等、能否查询结果，以及重复请求的代价。这个例子用于解释责任与证据，不预设所有 API 都有同一重试规则。

提出假设后给出区分它们的可观察证据。没有实际运行就标为推演或实验设计，不能把预期结果写成测试结果。

## 收束与继续

追问应来自新证据、真实回答、条件变化或尚未解释的机制；没有新增内容时不要换措辞无限追问。预算、关键证据或当前目标形成边界时，保留重要未解项并说明下一步。

持续主题可以在已有笔记里链接父问题和本轮增量，无需为每个问题创建 ID 或状态图。后续恢复从真实材料与未解项继续，不把上一轮摘要当成全部证据。
