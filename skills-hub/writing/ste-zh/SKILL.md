# 简化技术中文与英文

让读者清楚知道结论、条件、动作和结果，同时保留技术含义。应用到用户指定文本或明确选择的会话写作风格；不自动改变项目代码、注释或提交信息。用户切换风格时沿用新要求。

## 选择模式

| 任务 | 写法与参考 |
| --- | --- |
| 中文汇报、步骤、故障说明 | [中文写作](references/zh-rules.md)：结论先行、具体动词、清楚的条件与证据 |
| 英文说明文、README、评审 | [英文模式](references/english-modes.md)：默认实用写法，保持自然、准确和易读 |
| 用户明确要求 strict / ASD-STE100 检查 | 用其指定版本与可用规则/词典检查，说明检查范围和无法核验的项 |
| 一个对象有多个名称或中英混用 | [术语与歧义](references/terminology.md)：选稳定名称，保留项目已定义的技术词 |

## 改写时的判断

一个概念尽量使用同一名称；必要术语首次出现时解释。命令、路径、代码标识符、数字和日志原样保留，不能为了流畅改掉字面量。

一句承担一个主要意思，操作步骤用具体动词；条件影响动作时先说明条件。补齐含糊的主语和指代，把名词堆叠拆成关系。长句影响理解时拆分，不机械计算每句中文字数。

先给结论，再给支持结论的证据和适用范围。动作完成、检查通过、尚未验证和原因未知分别表达。保留不确定性，不把“可能”改成确定结论，也不为每句话添加同一套状态标签。

按内容选择段落、列表或表格。必要的故障原因与操作背景应保留，不强制省略所有过程，也不要求固定节名和汇报模板。

## 核对与交付

对照原文检查对象、否定、条件、数量、时序、责任与术语是否改变。用户只要求改写时交付完整改写稿；要求审查时指出具体歧义、影响和可替换句子。重大歧义无法消解时保留问题，不擅自补事实。

ASD-STE100 是英文标准；本技能的中文方法是改编，不是官方中文标准。没有对应官方规则与词典时，只能报告已执行的语言检查，不能声称合规认证。来源、许可与改编关系见 [NOTICE.md](NOTICE.md)。
