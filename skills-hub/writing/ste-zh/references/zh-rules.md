# 中文技术表达

采用明确对象、具体动词和可核对结果，保留自然中文。这里是本项目的写作方法，不是 ASD-STE100 的官方中文条文。

## 句子与结构

先写读者最需要的结论，再解释证据与影响。操作句写明谁对什么做什么；条件会改变动作时先给条件。含糊指代有两种理解时补出对象。

| 原句 | 更清楚的表达 | 保留的含义 |
| --- | --- | --- |
| 对配置进行相关优化 | 调整缓存配置，减少重复读取 | 明确动作与目的；目的须有材料依据 |
| 出现异常后进行处理 | 请求超时后，先查询任务是否已完成 | 补出异常、动作与时序 |
| 基本已经全部好了 | 已修复登录错误；移动端布局尚未验证 | 具体说明结果与未知范围 |
| 该配置可能存在不生效的问题 | 当前进程仍读取旧值；原因尚未确认 | 区分观察与原因判断 |

例子不能替原文添加事实。没有结果证据时应写“计划调整”，而不是“已减少重复读取”。

长句可以拆成条件、动作和结果，但不以固定字数判断质量。列表适合并列事项，表格适合可比较字段；普通因果说明用连续段落。

## 汇报与故障说明

完成和验证是不同维度：文件已改，检查可能尚未执行；测试通过，部署可能仍未完成。用自然语言说清本次事实，不强制每句带状态标签。

排错说明连接现象、证据、候选原因和下一步。尚未确定的原因可以保留“可能”“待验证”等准确表达，不能为了果断把推测改成定论。

引用日志、路径与错误代码时保留原文。读者需要操作时给可执行步骤，需要决策时给选项及后果，不在每次回复里堆齐所有模板。
