# 简历的选择、表达与排版

围绕岗位责任挑选经历。让读者快速知道做过什么、负责到什么程度、结果怎样，而不是把所有技术名和项目都放进去。

## 从事实写成果

每条描述通常包含行动、对象或范围、结果以及关键方法。顺序按最有价值的信息安排；没有可靠数字时保留具体的定性结果。

简历可以压缩叙事，面试再展开背景与取舍。不要为了套 XYZ 或 STAR 缺一项就发明数字、冲突或独立贡献。用户已有原句有清楚含义时，先改善动词与信息顺序。

技术词使用岗位能识别的名称，必要时首次并列全称和缩写。关键词应出现在真实经历或技能背景中，不能把 JD 中缺乏证据的词加入技能栏。

## 结构与版本

按用户资历和岗位组织经历、项目、技能和教育。单栏、标准标题和正文联系方式是稳妥起点；用户指定版式或行业需要时调整。页数根据有价值内容决定，避免以过小字号容纳冗余。

保留原件与岗位版本的区别。改动说明只解释实质取舍，例如删去哪类经历、强化哪个职责、哪些事实待补证，不要求每行附一份机械 diff。

## 导出与检查

参考 [工具说明](tools.md) 选择 Markdown、HTML、DOCX 或 PDF。导出后检查标题层级、项目跨页、联系方式、字体和数字是否完整。

需要机器读取时，检查文字能否正常选择或提取、阅读顺序是否正确。ATS 系统不同，单栏和可提取文字不能保证所有系统评分或解析都相同；不承诺“通过 ATS”。

检查最终 PDF 或 DOCX，而不是只看源 Markdown。导出失败时交付实际可用的格式，保留源文件和未完成项。
