# 诚实门

这是导出硬门，不是写作风格建议。

## 主张

- 每条可对外使用的数字、职级、时间、技术名都要有 `C-xxx`。
- 投递稿用 HTML 注释：`<!-- claim:C-012 -->`。
- `validate_claims.py` 对不上 evidence-map 时，不得把该文件当成品交付。
- 找不到数字就写定性描述，或标 `needs_proof` 并向用户要来源。不要编一个看起来合理的百分比。

## 四层

| 层 | 含义 | 能否进投递稿 |
|---|---|---|
| 事实 | 知识库或用户确认的原句 | 可以 |
| 估计 | 用户标过「约 / 量级」 | 可以，必须保留「约」 |
| 解释 | 你对动机、能力的归纳 | 只能进自我介绍，不能改写成事实 |
| 呈现选择 | 详略、顺序、用哪个同义词 | 可以，但不得升级范围 |

## 红线

不可改：学历、在职起止、公司法定名、正式职级、论文署名、仓库所有权。

JD 里有、语料里没有的技能，只出现在 match-report 的缺口表。

翻译是换角度讲真事。没有平台级证据，就不要写成平台。

提升计划里的未来完成时，不得写进「过去已经做到」。
