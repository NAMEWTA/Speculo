# 岗位投递与面试准备

从真实经历中选择与岗位相关的证据，交付用户这次需要的材料。只要自我介绍或一道面试题时，直接完成该项，不先补齐整套投递包。

## 从材料出发

复用用户提供的简历、经历、JD 和已确认偏好。只有会改变结果的材料缺口才询问；缺少 JD 时可以先整理经历，或按用户要求研究目标岗位并标明来源。
知识库只读取指定范围，用关键词定位相关内容，不把整库灌进上下文。大库可使用 [可选工具](references/tools.md) 建立可重建的文件索引。
保留个人经历与公司公开信息的区别。数字、职级、任职时间、学历和技能必须有用户资料支持；冲突先核对，不选较好看的版本。不把计划学习的能力写成已有经验。

## 按交付物组织

- 简历：按岗位挑选成果、责任和工具，使用清楚的动作与已有量化证据；没有数字就定性表达。JD 中未具备的能力列为缺口。
- 自我介绍：围绕与岗位相关的经历组织，默认完整稿约 3–4 分钟，用户时长优先；可给短版和可继续追问的项目。
- 面试题：由岗位要求、简历项目和真实缺口推导，答案绑定实际经历；不替用户虚构故事。
- 提升计划：区分近期表达/证据补充与需要学习的能力，每项有可检查的结果。
- 完整投递包：按需要组合上面材料，共用同一份经历依据，不重复抄写原件。

简历默认采用易读的单栏和标准章节，联系方式放正文。用户已有版式和页数要求优先，不为凑页数缩小到难读。
可使用 [render_resume.py](scripts/render_resume.py) 与 [resume.css](assets/resume.css) 输出 HTML，以及环境支持的 DOCX/PDF；具体依赖和限制见 [工具说明](references/tools.md)。检查实际排版和导出格式。

## 只保存可复用的资料

用户需要长期复用时，在已确定的工作区维护一份经历笔记，链接关键事实的原始来源；每个岗位保存 JD 和实际交付文件即可。重要数字可直接附来源，不要求 claim ID 或固定表格。
输出目录使用用户指定位置，或当前工作区下清楚命名的目录；不要写入技能包或修改原始知识库。无需双写配置、固定十九节档案或为空缺产物建模板。
交付文件、主要取舍和仍需用户补证的事实。没有执行的渲染或实际投递不要宣称完成。
