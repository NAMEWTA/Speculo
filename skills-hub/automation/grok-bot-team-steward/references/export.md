# 导出、覆盖与本地比较

用于团队快照和迁移准备。快照描述实际能取得的资料，不要求固定数量的文件。

## 从对象关系开始

先确定账号、具名 Bot 或团队范围，以及可以使用的资料来源。盘点角色、群聊、技能、routine 和连接器之间的关系，保持平台原 ID；同名对象不能直接合并。只读盘点或文件导出不自动发送消息给其他 Bot。

每种资料区分平台可直接导出、用户提供、Bot 自述和自己的摘要。自述可以补充上下文，但不能证明它已经覆盖平台全部历史。需要联系 Bot 时，沿用用户对该对象和动作的授权，避免让多个对象改写同一文件。

按恢复用途选择内容：

| 内容 | 需要保留的含义 |
| --- | --- |
| Profile | 名称、标题、简介原文及角色边界；头像可保留原文件或明确只有描述 |
| 技能 | 源文件、许可证、依赖、版本，以及哪些 Bot 启用了它 |
| routine | 完整指令、触发/时区、对象、启用状态、依赖连接器；最近结果只是观察 |
| 群聊 | 成员身份、用途和仍有效的共享约定 |
| 记忆 | 当前事实、重要决定、未完成工作、来源；过期内容单独标明 |
| 对话 | 能获得的原文、角色和时间范围；截断和缺失直接说明 |
| 工作文件 | 真正需要接续的项目与附件；不递归搬运整个家目录或浏览器数据 |

技能、配置、附件和可运行代码可以直接成为原件，不必抄成 Markdown。来源已是可长期定位的版本时，引用该版本通常比复制第二份更好。

## 一份入口记录

`snapshot.md` 可直接写明导出时间与账号、对象/文件位置、来源和覆盖、需要重新连接的服务、无法带走的资料。规模小就把对象内容放在同一文件；文件大时按对象拆分。路径相对快照根，便于移动。

中断时记下已经取得的资料和下一步，继续原记录。仅已读取近一个月对话时就写近一个月，不能补一个“完整”状态；空白文件也不能代表导出成功。

对话摘要突出当前决定、未完成线程和最近结果，明确它是摘要。保存真实用户原话时不为了顺畅改写；只因体积需要才切片，在消息边界切分并保持顺序。

## 脱敏与核验

令牌、cookie、认证文件、带密码的 URL、浏览器登录态和与任务无关的个人资料不进入快照。需要保留的业务资料按用户范围处理；脱敏说明写字段或路径，不重复暴露原秘密。

逐对象核对：所需角色能否找到全文、技能引用是否完整、routine 的时区和依赖是否可读、附件是否真存在、缺口是否写清。只校验文件数不能证明内容完整。

分享链接、发布快照或推送仓库按本次请求范围执行。原资料有许可要求时一并保留。

## 只读比较

先对齐对象 ID，再比名称和内容，区分重命名、创建、删除、配置修改与导出覆盖不同。原文和摘要不要直接逐字比较后宣称行为改变。

结果说明具体差异及影响，例如某 routine 的目标或时区变化、技能绑定缺失、某段记忆只在其中一份可见。只比较本地文件就不调用账号写操作，不联系 Bot，也不自动“同步”差异。
