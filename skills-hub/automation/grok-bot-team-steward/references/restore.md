# 逐对象恢复与接续

恢复先回答三个问题：目标账号里已经有什么、这份快照实际能恢复什么、本次请求授权恢复哪些对象。

## 预览与对象映射

读取快照入口和有关原件，核对账号、来源时间、资料覆盖及连接器缺口。已有对象按 ID 与配置确认，名称只是辅助线索。明确复用、更新、新建或暂缓的对象，说明会影响的群聊、技能和 routine。

用户只上传文件或要求预览时，交付可审查的结果；已明确要求恢复具名清单时沿用该授权。多份快照同时出现时，依据请求选定来源，不擅自混合角色来自 A、记忆来自 B。

恢复记录保留快照对象 → 目标 ID、实际动作和结果。对创建响应超时，先查目标现状与既有记录；只在确认未创建后重试。

## 按真实依赖推进

Profile 保留原名、标题和简介正文。若目标平台支持的配置不同，说明具体差异和可行替代，不用润色后的摘要冒充原配置。

技能先取得可读源和必要依赖，再安装并核对对应 Bot 的启用状态。平台只提供某种复制能力时，先验证其真实复制范围；不能假设一次 Duplicate 已包含记忆和历史。

群聊恢复成员和用途，检查每个成员映射是否正确。连接器记录重新连接的入口，凭据由既有安全流程提供，不从快照恢复登录态。

记忆与对话作为历史资料导入或提供给对应 Bot，说明其中哪些事实仍有效、哪些事项未完成、哪些内容已过期。需要发送资料给 Bot 时应在用户授权的团队联络范围内。核对导入后能否实际读取相关事实；不能以“文件已上传”代替可用性。

routine 恢复为暂停状态，核对执行对象、完整指令、日程/时区、连接器和输入资料。启用或试跑按用户指定范围执行；不要让旧记录中的启用状态自动触发新环境的外部动作。

## 部分失败与交付

一个对象失败只阻塞依赖它的工作，其他独立且已授权的部分可以继续。记录失败发生在创建、配置、绑定、导入还是运行验证，保留返回 ID 和可继续步骤。

完成时说明实际恢复和不能恢复的内容。常见未恢复项包括未提供的对话、原生时间线、OAuth/cookie、临时安装的软件和快照里缺失的附件；按现场事实列举，不套固定清单。

检查角色正文、技能绑定、群成员和暂停日程。用户要求的实际试跑另按结果记录，部分成功不概括为全队已恢复。
