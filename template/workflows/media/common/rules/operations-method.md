# 本地分发与运营复盘方法

## 边界
仅输出本地草稿、人工交接和人工导入反馈的复盘。禁止发布、上传、登录、评论、私信、付费API、排程与批量群发。获得发布授权也不在本能力中执行真实发布。

## 草稿
以核验母内容为唯一事实源，适配各平台受众与形式，交付标题、封面说明、图卡/插画位置与正文，不机械裁剪。平台限制需来源和核验日期，不永久硬编码可能变化的数字。

五个独立人工确认点为方向、平台与账号、标题、终稿、发布授权。前四项绑定完整内容、账号、版本和媒体字节，变化即失效；第五项只记未授权或外部人工交接，绝不是调用发布的许可。Agent不得自批；审批记录本身不是身份认证。

同包重复导出复用，人工编辑、冲突、已有锁或部分写入时停止覆盖。多渠道分别记录，不把一处完成当全部完成。没有真实人工回执就不称线上已发布。交付包含实际媒体副本与来源清单，不只是指向暂存目录的失效引用。

## 复盘与闭环
指标记录平台、账号、单位、来源、统计窗口与内容发布年龄；缺失保存null及原因，不写0。不同平台、窗口、形式不混成增长分数；一次样本只能提假设，不作因果结论。评论分事实纠错、理解问题、延伸需求和一般反馈；评论本身不是事实。

线上错误要列受影响渠道与人工更正待办，不能只改本地就声称线上修复。下一轮只改一个主要变量，例如前三秒Hook，记录对照、观察窗口、预期和混杂因素。实际同类内容跑通3–5条且失败/人工修改有证据后才建议固化，不以模拟数据满足门槛。

经用户确认通过永久知识网关沉淀Hook、旁白、镜头、字幕、视觉五类模板，保留来源、适用范围、版本和批准人；其他阶段只提交候选。不自动改核心方法。

## 交付
保存渠道完整草稿、批准/缺项、人工发布清单、复盘、下一轮简报和模板候选。无平台数据仍可复盘内容与制作，但注明不等于真实运营验证。完成标准必须形成具体下一轮决策，而不是“继续提升质量”。
