# 2026-09-14 环境归一化方案

**这是一份未执行的方案，不是已生效配置。** 先确认主用版本管理器与项目 pin；不得把统一目录理解成任意搬动所有 SDK。

建议 DevRoot：`~/AppData/Local/Dev`。系统/安装器管理的内容仍留在系统规定的位置。路径可以统一规划，但不要通过联接/符号链接掩盖配置混乱。

## 建议映射

| 对象 | 建议目标 | 约束 |
| --- | --- | --- |
| JDK / JAVA\_HOME | 由已确认的主用版本管理器解析 | 不把 JAVA\_HOME 写死到待淘汰版本；IDE、CI、项目分别验证 |
| Maven localRepository | ~/AppData/Local/Dev/data/maven/repository | 保留 settings.xml 官方锚点；备份未发布的 install 产物；不假设 MAVEN\_USER\_HOME 对所有版本生效 |
| GRADLE\_USER\_HOME | ~/AppData/Local/Dev/data/gradle | 整体包含配置/缓存/凭据；先停止 daemon，备份再验证 |
| Node 版本管理器 | 保留一个经确认的主用管理器 | nvm/fnm/volta/asdf/mise 不叠加争抢入口；原生 Windows 支持单独核实 |
| npm cache | ~/AppData/Local/Dev/cache/npm | 使用 npm 官方配置入口；不盲目设置全局 prefix；日志不等于纯缓存 |
| PNPM\_HOME / pnpm store | ~/AppData/Local/Dev/bin/pnpm / ~/AppData/Local/Dev/cache/pnpm-store | 两个不同概念；store 路径用本地版本支持的配置设置，注意项目所在卷与硬链接 |
| GOPATH / GOBIN | ~/AppData/Local/Dev/data/go / ~/AppData/Local/Dev/bin/go | GOPATH 可能是多路径并含源码；GOBIN 中有用户安装的工具 |
| GOCACHE / GOMODCACHE | ~/AppData/Local/Dev/cache/go-build / ~/AppData/Local/Dev/cache/go-mod | 清理影响离线构建；一般不设置 GOROOT；先检查 go env 和项目 toolchain |
| CARGO\_HOME / RUSTUP\_HOME | ~/AppData/Local/Dev/data/cargo / ~/AppData/Local/Dev/data/rustup | 非纯缓存；保护 credentials、config、bin、toolchain override；不要整目录自动迁移 |
| UV\_CACHE\_DIR | ~/AppData/Local/Dev/cache/uv | 先以当前 uv 帮助确认变量支持与现有配置 |
| UV\_PYTHON\_INSTALL\_DIR / UV\_TOOL\_DIR | ~/AppData/Local/Dev/data/uv/python / ~/AppData/Local/Dev/data/uv/tools | 解释器、工具环境与缓存分开；虚拟环境不保证可重定位 |
| UV\_TOOL\_BIN\_DIR | ~/AppData/Local/Dev/bin/uv | 确认 shell PATH 与已安装工具入口；避免和 pipx/系统 Python 重名 |
| mise/asdf/SDKMAN 等 | ~/AppData/Local/Dev/data 下各自专属根 | 仅建议；按已安装管理器的真实 OS/版本文档迁移；不默认安装新管理器 |

## 迁移顺序与验收

先备份配置与安装清单，确认没有运行中的 IDE、daemon、构建或安装。逐个生态迁移，不同时改所有变量。缓存优先让工具在新路径重建；含本地状态的目录按官方迁移方法处理。虚拟环境与绝对路径 shim 通常应重建。

先在新终端进行会话级验证，再修改单一持久化来源，最后重开终端、IDE 和构建任务验证。Windows 用户与机器 PATH 分开处理，禁止用 setx PATH 拼接覆盖；macOS 登录 shell、交互 shell、GUI 启动环境各自核实。

逐一检查 Maven/JDK 构建、Node/pnpm 安装与离线依赖需求、Go 测试、Rust override 与 cargo 工具、uv 项目及 tool 入口。需要网络的验证单独确认；失败则恢复原配置和原解析入口。旧目录只有在全部验证通过、唯一数据已备份并再次获准后才进入清理计划。

PATH 仅放必要的 bin/shims；不要加入缓存、库目录、整个 SDK 根或当前目录。项目级 pin、wrapper 与 lockfile 保留。详见 `references/20-toolchains.md` 和 `21-path-migration.md`。
