# 多余软件与卸载残留治理

“彻底清理”应表示清楚识别应用本体、后台组件、配置、个人数据和共享依赖，再按选择处理每一层；不是删除所有名称相近的目录。没有可靠使用记录时，不能用文件访问时间推断软件不再使用。

## 身份与冗余判断

先确认产品、发行商、精确 ID/bundle ID、版本、架构、安装范围和来源。多个注册表条目可能是同一安装；相同应用的 x64/arm64、长期支持版/开发版、用户版/机器版、商店版/传统版不自动等价。软件是否多余还取决于项目、插件、驱动、后台任务、许可证和其他使用者。

默认脚本没有完整软件使用频率、所有安装来源、服务/计划任务、系统扩展和全部收据证据。输出“需要人工核实”而不是“可全部卸载”。共享 VC++/.NET/WebView2、驱动、系统 Python/Java 和公共厂商组件默认保护。

## 分层执行

| 层级 | 需要用户选择/证据 | 执行与验收 |
| --- | --- | --- |
| 应用本体 | 精确身份、依赖、是否保留版本 | 官方卸载器或原生管理器，记录结果与重启需求 |
| 后台组件 | 服务/任务/登录项/扩展的实际归属及加载状态 | 按供应商卸载流程，验证不再加载；不能只删文件 |
| 应用配置 | 是否保留以后重装使用 | 逐目录/键确认，备份后清理明确归属项 |
| 个人数据 | 导出、备份、账号/许可证、删除范围 | 与卸载本体分开授权；未授权默认保留 |
| 缓存/日志 | 离线/诊断需求、进程状态 | 优先应用或管理器原生命令，验证占用变化 |
| 共享依赖 | 所有已知消费者和系统依赖 | 不因一个应用卸载就级联删除 |
| 路径/入口 | 真实 PATH 来源、快捷方式/shim 和归属 | 仅移除失效的对应入口，保持其他工具顺序 |

Windows 卸载入口核验 [WIN-3](00-sources.md#win-3)；macOS 核验 [MAC-2](00-sources.md#mac-2)、[MAC-3](00-sources.md#mac-3)；Homebrew 核验 [BRW-1](00-sources.md#brw-1)。本次未在线访问这些文档，执行时仍需本机版本检查。

## Windows 残留

对照已确认的安装位置、发行商、卸载结果和实际加载状态检查 AppData/ProgramData、Run、服务、计划任务、快捷方式和 PATH。注册表 UninstallString 是数据，不能不经校验就交给 shell 执行；不猜 MSI 产品 GUID，不随意取所有权，不卸载共享运行库来降低“软件数量”。

卸载后存在同名目录可能是用户数据、其他版本或其他产品共用位置。保留/删除个人数据需明确选择。不要把 Windows Installer 缓存当应用卸载残留整体清除，也不要调用注册表清理器批量“修复”。

## macOS 残留

对有后台组件、网络/文件系统扩展或驱动的产品优先官方卸载器。移除 app bundle 后，再根据 bundle ID 与供应商文档检查 LaunchAgents/Daemons、登录/后台项、Preferences、Application Support、Containers、Group Containers、Caches 和 Logs。

Group Containers、厂商共用组件、钥匙串、浏览器/邮件资料和系统收据不要按字符串模糊匹配删除。Homebrew `--zap` 或第三方卸载器的广泛规则也需要逐路径复核；“受管理工具支持”不等于“用户已同意删除个人数据”。仅遗忘 pkg 收据不等于卸载实际文件。

## 执行日志与验收

每个 U 类动作记录用户选择、精确身份、原生工具、命令/参数的已核实来源、退出结果、重启要求、后台组件状态、被处理目录、保留资料与失败项。不能把退出码成功当作所有残留均已清除。

卸载后重跑只读报告，与之前清单比较。启动项失效、目录残留、PATH 失效分别列出；无法归属的项保留。迁移到同类替代软件时先验证数据导入和工作流程，再卸载原软件。永久删除的个人数据没有脚本级恢复保证。
