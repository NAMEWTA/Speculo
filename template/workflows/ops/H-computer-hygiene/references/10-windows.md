# Windows 专项检查与清理

**适用状态：命令和系统能力须在真实 Windows 版本上核实。** 本包未在线查阅最新文档，未进行 Windows 真机验收。官方入口见 [WIN-1 至 WIN-6](00-sources.md#win-1)。原生 Windows、WSL、容器和其他账户分别检查，不跨边界直接搬动 SDK。

## 采集与证据

默认 Python 分支读取 HKCU/HKLM 的 Win32 卸载键（32/64 位视图）、Run 项名称、指定持久化路径变量和当前进程 PATH。只记录卸载命令是否存在，不执行或导出其完整参数。注册表清单可能重复，不能当作完整软件数据库。

商店/Appx 应用、服务、计划任务、驱动、后台包、WSL、容器、系统恢复点和其他用户状态未由默认脚本完整采集。需进一步检查时，在可信且已授权的 PowerShell 中使用本机支持的原生命令，仅提取必要字段。不要为了应用盘点调用 `Win32_Product` 或相关 WMI 查询；它不是本工作的检测接口。查软件身份时交叉核对“已安装的应用”、发行商与原始安装器。[WIN-3](00-sources.md#win-3)

## 清理矩阵

| 对象 | 检查要点 | 建议处理 | 风险与禁止项 |
| --- | --- | --- | --- |
| 用户 Temp、CrashDumps、WER | 所有者、进程、时间、体积、是否正在写入 | 优先设置里的临时文件/存储清理；日志按需保留 | 不按扩展名全删，安装中的临时目录保留 |
| 回收站 | 是否含待恢复文件、其他卷 | 用户单独确认后清空对应范围 | 不把“回收站”视为默认授权 |
| 下载目录安装包/压缩包 | 已安装版本、离线安装需求、许可证/校验文件 | 列候选，确认原件与备份后处理 | 时间久不代表不用；不删除文档与项目压缩包 |
| Windows.old / 更新回退材料 | 当前是否需要系统回退、升级后验证是否完成 | 用系统存储清理入口 | 会影响回退能力；不硬编码保留天数，不直接删目录 |
| WinSxS / 组件存储 | 先使用原生分析和系统维护 | 仅通过受支持 DISM/计划维护 | 禁止资源管理器/脚本直接删除；默认禁止 ResetBase |
| `C:\Windows\Installer` | MSI 修复/更新/卸载关联 | 保护 | 不用“孤立 MSI 文件清理器”推断可删 |
| Delivery Optimization / 更新缓存 | 系统状态、待安装更新、重启需求 | 使用系统支持的清理入口 | 不自行停服务、取得所有权后清空组件目录 |
| 浏览器/聊天/邮件软件 | 缓存和个人资料严格分开 | 优先应用内清理 | 不清除 profile、cookie、会话、扩展、邮件库或下载证据 |
| 休眠文件 | 是否使用休眠、快速启动和当前电源需求 | 仅列为可选功能取舍 | 不是常规“优化”；不默认执行 `powercfg /h off` |
| pagefile / 内存转储 | 内存、崩溃诊断与应用需求 | 系统管理优先 | 不默认关 pagefile、不硬编码“最优值” |
| WSL `ext4.vhdx` | 发行版身份、Linux 内部空间、备份 | 在 WSL 内另跑检查；压缩按官方流程 | 禁止直接删除 vhdx 或把它当普通缓存 |
| Docker/虚拟机磁盘 | 容器卷、镜像、数据库与快照 | 用所属平台的原生检查工具 | 禁止默认 `system prune --volumes`；卷可能是唯一数据 |
| 共享运行库/驱动 | VC++、.NET、WebView2、设备与应用依赖 | 默认保留，精确核实 | 同时安装多个版本/架构可能必要，不是冗余证据 |

系统存储入口、WinSxS 原生维护、休眠设置和 WSL 空间规则分别核验 [WIN-1](00-sources.md#win-1)、[WIN-2](00-sources.md#win-2)、[WIN-5](00-sources.md#win-5)、[WIN-6](00-sources.md#win-6)。

## 环境路径治理

建议 DevRoot 为 `%LOCALAPPDATA%\Dev`，按 data/cache/config/bin/tmp 分层。这个建议仅管理用户自己的工具状态，不搬动 Program Files、Windows、Scoop/winget/MSI 管理的应用安装树，也不复制一套 JDK 到新路径后直接删除原安装器记录。

当前进程变量、用户持久化变量和机器变量不是同一个状态。分别备份变量名、原值、注册表类型和 PATH 顺序，保留 `%变量%` 的原始展开语义。不通过 `setx PATH "%PATH%;..."` 或类似拼接覆盖 PATH；只修改已经定位的来源与条目，避免把展开后的全局 PATH 复制进用户 PATH。[WIN-4](00-sources.md#win-4)

nvm-windows 和 POSIX nvm 是不同工具；NVM_SYMLINK 是解析入口，不是任意可删除目录。fnm 的会话路径不必作为永久目录统一。PowerShell、cmd、Git Bash、IDE 和服务账户的环境分别验证。WSL Linux 工具应位于 WSL 的合理文件系统，不与 Windows 二进制、大小写规则和 ABI 混用。[NVM-1](00-sources.md#nvm-1)、[NVW-1](00-sources.md#nvw-1)、[FNM-1](00-sources.md#fnm-1)

## 软件彻底卸载

先确认精确应用 ID、发行商、版本、架构和安装范围。使用已确认的系统/官方卸载器；只有本机 winget 帮助支持、应用匹配正确时，才按精确 ID 生成 `winget uninstall --id <ID> --exact` 类计划。命令里的 ID 必须来自真实记录，不能从名称猜测。[WIN-3](00-sources.md#win-3)

卸载完成并按需重启后，再查该应用明确归属的启动项、服务、计划任务、目录和 PATH。删除个人数据另行确认；ProgramData、AppData 中共享厂商目录不能整树清空。安装器缓存、共享运行库和驱动不随应用名称模糊匹配清理。卸载字符串来自注册表的数据，不是默认可信指令。

## 不做的“优化”

不关闭 Defender/更新/防火墙，不改未知注册表，不移除系统商店框架，不清理 Prefetch 或内存来制造性能提升，不删除共享 DLL，不批量禁用服务。空间回收和性能改善是不同目标；没有测量就不声称会提速。
