# 层级路由与一次任务授权

本文件拥有范围选择和任务级授权规则。执行能力、路径保护、单计划批准和双边回执仍由 README、原 spec/plan schema 及执行器负责。

## 范围必须显式

| 用户目的 | scope / Work | 必需输入 | 明确不做 |
| --- | --- | --- | --- |
| 准备发起操作的本机 | controller / I | 控制端 ID、绝对 state 根 | 不默认把本机登记为服务器 |
| 接入一台服务器 | access / S | 一个 server_id、可信连接与身份、首次根选择 | 不部署项目、不自动信任主机密钥 |
| 配置系统环境、Docker、Nginx | server / H | 一个已登记 server_id | 不从 cwd 推断 project |
| 安装 APP 或共享服务 | project / D | 一个 project_id、明确 server_ids、真实需求 | 不猜服务器、不把主机级入口伪装成 APP |
| 看服务器/项目清单 | inventory / V | 已初始化 state 根 | 不联网、不部署、不授予后续操作权限 |

服务本身是用户交付项目（如公共 MySQL）时走 D；为整个服务器提供基础入口的 Nginx/WireGuard 走 H。项目包含服务反向代理配置不自动拥有整台机器的系统修改权限。用户已给出的目标直接使用，不重复询问；名称无法唯一解析时只阻塞该目标，先完成无歧义只读分析。

## 确认任务后，展示 Plan Mode 然后执行

用户明确说“按计划实施/重构并执行/部署到指定服务器”属于实施请求；只说“分析/给计划/看看”不构成执行授权。入口先写清目标、服务器与项目、前置检查、固定来源、持久化、依赖顺序、网络与账号影响、备份恢复、健康检查、完成条件、保留/删除边界，再开始执行；不在每步重复询问“是否继续”。

任务文件不是授权来源。`task-plan` 保存详细 PLAN.md 与冻结的 H/D specs，返回 task_digest；入口已展示计划且存在明确实施请求时，用 `task-authorize` 记录该原始请求的真实确认语句/来源和确认者，再直接 `task-run`。不要求用户手动执行这三个命令，不伪造用户逐一看过未来 Run digest。

H 入口选择一台明确服务器；一个 server 任务可以串行多个 H 步骤，并显式列出包括文档/依赖影响在内的所有获准服务器，不允许变成 D 部署。

任务授权固定一个 Controller、显式服务器、一个主项目（server scope 无主项目）、已声明的影响/依赖项目、1–20 个有序规格、最长 24 小时有效期、执行器摘要、连接/known_hosts 内容、凭据账本、input_paths 文件树。输入每文件 ≤16 MiB、总计 ≤256 MiB/10000 文件；大构件使用经审阅的固定摘要下载适配，不内嵌大二进制。H 影响已有服务时把相关项目和 acknowledged_consumers 全部写清。

运行器针对每个冻结规格在执行前重新编译实际现场计划，检查声明范围、依赖消费者、编译器完整修改集、源码摘要，再写入 `approved_by=task:<task_id>` 的关联批准；之后调用原 apply。H 为 D 准备环境产生的受控状态变化可在同一任务中继续；无法提前明确的新规格、额外服务器/项目或现场不确定性不能自动扩展。通用自定义命令仍是已审核可执行代码，不是系统调用沙箱；尤其须审核下载来源、安装器、命令引用文件和实际持久化参数。

`allow_policy_changes`、`allow_public_ingress`、`allow_destructive` 必须显式声明。迁移、退役、purge-quarantine 还需独立的 `I-APPROVE-THIS-EXACT-DESTRUCTIVE-TASK` 范围确认；它可以包含在原任务授权中，但不能从普通部署请求推断。业务数据删除仍不是默认能力。

## 停止与恢复

首次任务执行要求资源修订未在准备后发生变化；每步开始前复核身份、连接、输入、凭据、执行器和有效期。计划过期/漂移、未知目标、缺权限、真实输入缺失或锁冲突只阻塞受影响动作，不以“要再确认一下”为由重复打断已授权正常步骤。

一旦出现 failed、partial、unknown 或 docs_pending，停止后续步骤并保留 progress、Run 引用、原计划/日志/双边回执。任何 started.json 都禁止 task-run 自动重放，包括已完成任务。不能用新的 task_id 包装同一未知操作以绕过恢复。先 inspect-run，遵循 recovery.md；需要修复或重新部署时形成新的明确规格与任务边界。

正常完成必须以原 apply 返回 completed 且双边回执成立为准，再生成 V 的本地视图。V 失败记为“执行结果已保存、视图生成失败”，不能重跑业务。文档或索引不会自动变成永久知识；知识写入仍走原 owner/gateway 并获得独立同意。

首次根选择按 <Path>{roots.workflows}/ops/common/rules/host-root-and-onboarding.md</Path> 执行。server-root-confirm 只记录真实用户路径决定，不代替安装授权；已有明确指定不重复询问。当前任务编排只接入 H/D；I 初始化和 S 的首次信任建立/固定 Node bootstrap 保留原网关，不用任务授权掩盖缺失的 SSH 登录条件。
