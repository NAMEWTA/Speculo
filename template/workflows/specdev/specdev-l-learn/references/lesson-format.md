# 学习图解格式

写图解与分配编号时读取；这是产物格式权威，不是另一套学习状态。

## 输出格式

在选定或本轮新建 change 的 `<Path>{roots.state}/specdev/changes/{change}/learning/</Path>` 内原子写入一份新的 `<Path>{roots.state}/specdev/changes/{change}/learning/{number}_{topic}.md</Path>`，并原子更新索引 `<Path>{roots.state}/specdev/changes/{change}/learning/index.md</Path>`。这些产物属于 SpecDev change，不写入 `<Path>{roots.state}/learning/</Path>`。文档必须是纯 Markdown，不生成 HTML、CSS、SVG、图片链接或浏览器专属交互；文字来源链接可以使用普通 Markdown 链接。

`<number>` 是两位起始、持续递增的序号：先核对索引与同目录真实图解，恢复未闭合的追加，再取两者最大序号加一，因此第一次为 `01`，下一次为 `02`，超过 `99` 继续 `100`；不为旧文件重编号。`<topic>` 是主题的简短、可作文件名的标签，可使用中文、字母、数字、`-` 或 `_`，但不能含空格、`/`、`\\` 或 `..`。同主题再次解释也创建新编号文件，同一编号不能分配给多个文件。

索引是唯一目录，使用下列 Markdown 表格；每新增一份图解就在表末追加一行，并保留既有行。文件列只写同目录的文件名：

```markdown
# 学习图解索引

| 编号 | 文件 | 主题 | 简介 |
| --- | --- | --- | --- |
| 01 | 01_<topic>.md | <主题> | <一句话说明它解释什么> |
```

已有 `# Change 学习图解索引` 属于历史产物格式，保持原题头和历史行，仍可追加；新索引使用上面的标题。

## 追加与部分失败恢复

图解文件使用无覆盖的原子创建，索引用写前原字节检查和原子替换；两次写入不是整体事务。先保存图解，后追加索引，再回读两者。目标已存在或索引已被其他 writer 改动时停止重叠写入，保留已落地文件，不覆盖、不删历史、不抢占编号。

恢复先核对原会话和真实文件：本轮完整图解已创建但未登记时，验证正文后补入原编号行；索引已经登记则直接验证，不重复追加或重新生成。出现缺文件、断号、重复编号、不完整正文或未知 owner 的孤立文件时，报告冲突与恢复位置，由原 writer 处理后再分配下一号。不能靠重新编号或跳过旧记录掩盖失败。

按主题选择最贴切的图，但优先用多个短小 ASCII 图代替长文字：

```text
结构图：
[系统]
  |
  +-- [部件 A]
  +-- [部件 B]

数据流图：
[输入] -> [处理] -> [结果]

调用流图：
[用户动作] -> [入口] -> [服务] -> [回应]

状态变化图：
[等待] -> [进行中] -> [完成]
```

每份图解至少包含以下四节：

1. `## 先看全图`：一个能说清“谁和谁有关”的 ASCII 图。
2. `## 一步一步看`：按箭头顺序解释。流程、数据或调用会移动时，再给对应的 ASCII 图。
3. `## 术语小词典`：只保留读图必需的词。每个词先用日常语言解释，再给它的专业名字。例如：`临时便签（缓存）`，意思是“把常用结果先放在手边，下一次不用重新找”。
4. `## 你现在能复述什么`：用短句归纳“它是什么、为什么需要它、它怎样流动或被调用”，列出仍未讲清的问题；这是复述提示，不是用户已经掌握的判定。

图中的方框名称使用普通名词和动词，不用缩写；箭头必须有方向。一个图只讲一个问题。确有边界、失败或例外时，单独画一张小图说明，不把它塞进主图。

## 解释依据

在原四节中就近引用文件、章节或 URL，记录适用版本/修订；区分源码事实、作者观点、实际测试验证、可定位理由、类比、推断与未知。没有运行测试不写“已通过”，外部文章的说法不自动成为本项目事实。旧 Spec、文章与实现不一致时说明差异；需要时用小图展示真实失败与恢复方向，不编造事故。

带着需求学习时，在“一步一步看”中说明参考思路解决的问题、可借鉴部分和适用条件；把本项目尚未决定的取舍留作问题，不生成实施计划或授权结论。新理解追加编号，不改旧文件，不增加其他格式产物。
