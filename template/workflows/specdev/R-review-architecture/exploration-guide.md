# 探索指南

有机遍历代码仓以发现架构摩擦，将每个摩擦点转化为可操作的深化候选。使用 `<Path>{roots.workflows}/specdev/I-implement/codebase-design-glossary.md</Path>` 中的术语——module、interface、depth、seam、adapter、leverage、locality——一致地描述每个发现。

## 探索方式

使用 Agent 工具的 `subagent_type=Explore` 遍历代码仓。不遵循僵化启发式——有机地探索，注意你在何处遇到摩擦。目标是发现将浅模块转化为深模块的机会。

## 摩擦信号

探索时注意以下信号，每个信号指向一个潜在的深化候选：

### 浅模块

模块的接口几乎和实现一样复杂——大量方法、复杂参数，但内部仅是透传或简单委托。

识别方法：
- 模块的方法数量接近或超过其内部逻辑行数
- 调用者需要理解多个方法才能完成一件事
- 模块仅仅是另一个模块的重命名包装

### 接缝泄漏

两个模块的接口边界存在泄漏——一方的实现细节暴露给另一方。

识别方法：
- 调用者需要了解被调用模块的内部数据结构
- 修改一个模块的实现需要同步修改调用者
- 错误处理分散在调用链的多个层级

### 局部性缺陷

理解一个概念需要跨多个小模块反复跳跃——相关代码分散而非集中。

识别方法：
- 修改一个行为需要编辑 3 个以上文件
- 纯函数仅为可测试性提取，但真正的 bug 隐藏在调用方式中（无局部性）
- 同一领域的验证逻辑散布在多处

### 不可测试代码

模块难以通过其公共接口测试，或根本未经测试。

识别方法：
- 模块在构造时创建依赖而非接收依赖
- 模块产生副作用而不返回结果
- 测试文件不存在，或测试绕过接口直接操纵内部状态

### 单一适配器接缝

接口只有一个适配器——仅为了"以后可能替换"而引入的接缝。

识别方法：
- 接口只有一个实现类，且无测试替身
- 接口的存在理由是"解耦"，但依赖方向并未改变
- 接口的方法签名与唯一实现完全一致

## 删除测试

对每个可疑模块应用删除测试：

1. 想象删除此模块
2. 如果复杂性消失——它只是透传层 → **浅模块，候选合并**
3. 如果复杂性在 N 个调用者中重新出现——它在发挥价值 → **保留，或深化其接口**

删除测试的核心洞察：一个模块的价值不在于它做了什么，而在于如果它不存在会发生什么。

## 接缝评估

对每个候选评估其接缝质量：

- **接缝位置**：接口放在哪里？调用者和实现之间的边界是否干净？
- **适配器证明**：是否存在至少两个适配器（生产 + 测试）来证明接缝是真实的？一个适配器意味着假设性接缝。
- **依赖类别**：接缝处的依赖属于哪个类别？参见 `<Path>{roots.workflows}/specdev/I-implement/deepening.md</Path>`——进程内、本地可替换、远程但自有、真正外部依赖。类别决定了深化后的测试策略。

## ADR 冲突检测

探索中对照已有 ADR 检查每个候选：

1. 读取 `<Path>{roots.state}/specdev/adr/</Path>` 下所有 ADR 文件
2. 读取 `<Path>{roots.state}/specdev/changes/{change}/ADR.md</Path>` 中的本变更决策
3. 如果候选方案与已有 ADR 矛盾：
   - **摩擦真实且值得重新审视** → 在候选卡片中以警告框标注（例如："与 ADR-0007 矛盾——但值得重新审视因为……"）
   - **ADR 理由仍然成立** → 不提出该候选——不要列出 ADR 禁止的所有理论重构
4. 仅在探索结束后统一评估，不要在探索过程中逐条争论 ADR

## 候选记录格式

每个候选在内部记录以下信息，供步骤 3 生成报告使用：

- **涉及文件**（路径列表）
- **摩擦类型**（浅模块 / 接缝泄漏 / 局部性缺陷 / 不可测试 / 单一适配器）
- **问题描述**（一句）
- **解决方向**（一句——深化模块、合并浅包装、重划接缝、引入适配器）
- **依赖类别**（进程内 / 本地可替换 / 远程但自有 / 真正外部依赖）
- **删除测试结果**（"复杂度集中"或"复杂度转移"）
- **推荐强度**（Strong / Worth exploring / Speculative）
- **ADR 冲突**（如有——引用 ADR 编号和重新审视的理由）

推荐强度判断：
- **Strong**：删除测试通过（复杂度会集中），接缝有两个以上适配器，依赖为进程内或本地可替换
- **Worth exploring**：删除测试通过但依赖为远程或外部，或接缝仅有一个适配器
- **Speculative**：删除测试结果不明确，或预期的深度提升较小
