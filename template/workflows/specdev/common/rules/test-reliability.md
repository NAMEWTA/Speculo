# 测试可靠性与反例验证

新增、修改或诊断异步、并发、共享资源、进程、时钟或平台相关测试时读取。这里决定测试怎样可信；命令选择与证据复用由 <Path>{roots.workflows}/specdev/common/rules/evidence-and-verification.md</Path> 负责，失败保证见 <Path>{roots.workflows}/specdev/common/rules/error-handling.md</Path>。

## 按真实拓扑设计

核对测试文件、worker、独立测试进程和 CI job 是否并行。进程隔离不隔离端口、文件名、数据库、外部服务和继承的子进程。每项资源都要说明 owner、原子取得方式、就绪信号、已注册的清理和清理完成信号。不要因为一个 fixture 没隔离，就将整套测试串行化。

端口让系统分配并在 listening 后读取，不能先扫描空闲再绑定；临时目录用系统唯一分配，数据库/会话/输出使用测试私有命名空间。录制数据的稳定标识与真实临时地址分离。纯解析输入中的固定 URL 不代表占用了资源，不机械改写。

## 全局状态与时序

优先依赖注入或实例局部替身。必须修改 env、cwd、时区、假时钟、注册表、fetch 或全局 mock 时，记录原值是否存在，立即注册恢复，用最小 try/finally 恢复原状态；只拦截测试拥有的请求。并行测试不能共享未协调的全局可变状态。

等待握手、事件、状态或 owned promise；固定 sleep 只可提供已验证状态之后的展示停留，不能证明就绪。竞态用 barrier/deferred 明确安置交错，并证明实际重叠；压力复跑只是补充。超时只限制等待，不能成为断言成立的条件。测试本身验证 deadline 时，外层等待必须与被测 deadline 分开。

## 清理必须完成

资源取得后立即登记清理。停止新请求、解除监听、恢复全局状态、终止 owned work，并等待 server close、child exit、worker termination 等实际完成信号。abort/close/kill 返回不等于安静退出；验证延迟回调不能再污染下一用例。清理失败保留原故障及清理故障，不吞掉其中一个。

遵循项目支持的平台和引擎范围。操作系统拥有的时间精度、环境变量大小写、权限、信号与文件句柄语义，用平台实际读回值或有理由的特定跳过处理，不削弱所有平台的断言。只在识别等待对象和真实预算后调整 timeout，setup/teardown 使用一致预算。

## 证明会拒绝目标错误

行为修复尽可能观察修复前 red；静态门禁必须通过真实入口拒绝一个受控无效例，再恢复并复跑。编译失败、没选中测试、错误 fixture 或未落地的变异不是目标 red。跨进程隔离修复需要并发独立进程证据；只在单进程顺序运行不足以证明它。

不能通过加 sleep、无依据重试、全局串行、吞错、弱化断言或归一化掉真实行为来修复 flaky test。外部服务确有瞬态故障时，按项目约定使用有预算的重试并记录，不迁移到确定性的本地测试。

替换旧测试前按行为/错误/兼容/安全/恢复风险映射到新测试；原风险未被承接时保留或补测。覆盖率和测试数量不能证明等价。结构检查、可执行反例和真实宿主观察分别报告，不把第一层写成第三层。
