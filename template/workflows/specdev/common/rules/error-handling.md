# 失败、状态保证与安全恢复

设计或修改错误、重试、取消、后台任务、持久化或远程副作用时读取。规范失败后的行为，不建立新的错误注册表或任务状态库。远程去重、授权和回执仍使用 <Path>{roots.workflows}/specdev/T-triage/remote-operations.md</Path>；执行证据由 <Path>{roots.workflows}/specdev/common/rules/evidence-and-verification.md</Path> 拥有。

## 先定义失败后的事实

为每个会影响调用方行动的失败说明：失败类别和稳定身份、处理与报告 owner、状态是否仍有效、副作用是未发生/部分发生/已提交/未知、资源清理责任、下一安全动作。优先复用项目已有类型和错误约定；机器分支使用稳定代码或判别字段，不解析错误文案。不为普通内部异常机械建立复杂错误层级。

捕获异常只阻止传播，不撤销已经发生的修改。只有状态 owner 能依据不变量确认可以继续；否则停止依赖该状态的工作、丢弃不可信实例或升级处理。记录日志、返回空值、重新渲染 UI 都不等于恢复。意外缺陷不能被包装成成功。

## 重试与取消

有限操作的重试必须有安全重复依据、预算、取消方式和唯一 owner；持续监督任务则需要生命周期 owner 和可观察的降级状态。使用现有 config/Plan 的预算，不在下游偷偷扩大次数。先检查实际外部状态，再决定未知结果能否重试；只读也可能依赖已变化输入，仍需核实范围。

取消必须说明停止接收、停止执行和外部工作终止各自的时点。超时返回、AbortSignal 触发或 kill 请求发出，都不证明远端/子进程已经停止。等待 owner 的完成信号；无法确认终止时保留未知状态和后续核实责任。禁止在不可信状态上 catch-and-continue。

## 可见报告

最终错误至少说清：哪个操作受影响、已知影响与未知部分、系统已经停止/保留/降级什么，以及安全下一步。不得承诺未被证明的成功、回滚或安全重试。持续无效状态应持续可见；主报告通道失败时使用独立的安全回退通道。显示遵循项目已有语言和本地化机制；敏感值与内部凭据不得进入用户提示或持久化证据。

## 校准与验收

- 请求创建 PR 超时：先按原 marker/目标核实；没有返回结果不是没有创建。不能直接重复创建。
- 解析配置在任何写入前失败：修正输入后可以重新尝试，但不能因此推断所有运行期失败都可重试。
- 本地写入完成但确认响应丢失：副作用可能已提交；需核对内容/版本，不声称已回滚。
- 自报 caught=true：不是成功证据。测试检查实际文件、事件、外部状态、清理完成和最终可见报告。

S 记录用户可见保证，Ticket 绑定验证与停止点，I 实现，D 区分事实和解释，C 跟踪所有可达执行入口。原 Work 继续拥有 Evidence、LOG 和恢复键；此规则不获得额外写权限。
