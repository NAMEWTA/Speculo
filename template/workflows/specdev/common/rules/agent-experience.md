# 面向 Agent 的工具与上下文体验

设计或修改工具名称/描述/参数、prompt、Work/Skill 触发、上下文加载或多步工具流程时读取。普通代码修改不自动触发全库提示词审查。真实项目 Skill 定位与调用继续遵守 <Path>{roots.workflows}/specdev/common/rules/skill-invocation.md</Path>，本规则不增加另一套注册目录。

## 发现与执行

先展示目的、可用动作和关键限制；只有命中任务的正文和当前分支 reference 才展开。description 使用真实任务/时点和相邻非触发例，不用资深角色自我介绍代替路由。每个延后资源都有可理解描述及可靠获取方式；摘要不能代替加载正文，已由当前调用完整注入的正文不重复加载。

同一任务中相同摘要的规范不机械重读；范围、身份、版本或相关依赖漂移时重读需要的部分。永久知识先定位条目再回读必要原文；不得为节省上下文删除前置授权、破坏性效果和必需验证。

## 工具定义与结果

名称和描述说明可观察行为、输入输出与限制，不暴露无用内部执行机制。参数自己的默认值、范围、配对和条件写在参数处，不跨工具重复。项目本已有稳定错误身份时使用它，不靠解析展示文本调度。

结果有界，给出状态、必要邻接上下文、标识和详细读取位置；截断和省略必须明确。分页未完整不能报告穷尽；有结果句柄不意味着结果已读。要能区分无结果、读取失败、权限不足和不完整视图。失败后的副作用与安全动作按 <Path>{roots.workflows}/specdev/common/rules/error-handling.md</Path>。

## 对模型实际看到的内容验收

检查每种适用模式中的最终 prompt、schema、结果、错误和取消/恢复提示，而不是只看源字符串。增加该调用、失败、空结果、截断后继续读取等真实行为场景；权限必须在实际执行入口生效，描述和 YAML 字段本身不提供强制授权。

相同请求反复工具调用、换问法但没有进展、服务端报错后的无限重试，要记录已尝试方法与新增证据。使用原 I/P 的停止和恢复规则，不新建无限自动循环；仅更换 Agent 或清空计数不是新方法。

评估总体工作：实际初始/后续输入量、读取次数、错误和任务完成情况。只减少字符却增加查找或误用不算改善；没有可比宿主测量时，只报告真实字符与文件范围，不推算 Token、账单或套餐节省。

正例：目录说明用途，选中后加载对应 Work 和当前 reference。反例：仅凭目录描述执行危险步骤，或每次把全部 Work 正文再次灌入上下文。
