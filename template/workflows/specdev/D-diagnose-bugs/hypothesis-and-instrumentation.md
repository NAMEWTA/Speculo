# 假设与单变量插桩

只在反馈回路已变红并最小化后加载。

## 排名假设

在测试前生成 3–5 个候选，按证据支持度、解释范围和验证成本排序。每个候选使用：

> 如果 X 是原因，那么改变 Y 会让红灯消失，或改变 Z 会使其更明显。

无法给出可观察预测的候选不是假设。测试前向用户展示排名；用户 AFK 时记录该 checkpoint 并按排名继续。

## 探针

每个探针只映射一个预测，一次只改变一个变量：

1. 环境支持时优先 debugger 或 REPL；
2. 其次在区分假设的边界放置定向日志；
3. 每条临时日志使用同一唯一前缀，如 `[DEBUG-a4f2]`；
4. 性能分支建立计时/分析器/查询计划基线，再执行二分；
5. 不使用“记录全部再 grep”代替实验设计。

## 根因确认

确认项必须同时解释触发条件、失败机制、漏检原因、影响范围、修复为何阻断机制及回归风险。只能缓解症状时标为 workaround。没有正确测试 seam 时记录架构发现并路由 Architecture Review。

## 完成门

- 每个已测候选有预测、实验、结果和结论；
- 确认根因能让红灯出现和消失；
- 其他高排名候选有区分性反证；
- 临时探针有唯一前缀、owner 和清理结果。
