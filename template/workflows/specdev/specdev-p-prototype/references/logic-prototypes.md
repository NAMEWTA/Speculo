# 逻辑原型与可行性试验

用于验证规则、状态转换、算法、接口行为、性能边界或外部依赖可行性。先写清会影响决定的假设与可观察结果，再做最小试验。

沿用适合项目的语言和运行方式，隔离模拟输入与真实服务。试验代码可以是小脚本、测试、notebook 或可交互页面；不要求 UI DESIGN、固定目录或专用包 schema。

除正常例子外，选能够推翻方案的边界或反例：空输入、重复、顺序变化、失败、取消、极限数据或恢复。是否连接真实外部系统由当前任务范围决定，模拟结果只支持模拟条件。

记录输入、命令、版本与实际输出，说明哪些现象支持假设、哪些仍未知。演示成功不证明生产可靠性；比较方案时使用同一任务与工作量。

保留有复用价值的试验源和结果，规格直接引用它们。准备进入生产实现时重新评估错误处理、权限、持久化、可维护性和测试，不把探索代码未经检查当成正式模块。
