# 布局与信息基础

先说明用户来这里要完成什么、面对什么对象、需要同时比较哪些信息，以及何种操作最常发生。页面外观从这些约束生长，技术栈名称不能推导设计。

## 六种常用结构

| 结构 | 适合的任务 | 设计时的关键问题 |
| --- | --- | --- |
| 全局侧栏 + 内容 | 多个稳定业务区域或产品模块 | 全局导航与当前页面操作是否分层，低频入口是否抢占空间 |
| 图标轨 + 上下文侧栏 | 工具多、切换频繁、用户熟悉领域 | 图标是否可识别，展开后的上下文是否一致，窄屏如何进入 |
| 主列表 + 详情 | 连续浏览、比较或处理大量对象 | 选择、筛选、滚动位置和返回路径能否保持 |
| 编辑器或画布 + 属性面板 | 内容、图形或配置的连续编辑 | 主工作区面积、焦点、撤销、选中对象与属性对应是否清楚 |
| 仪表盘与网格 | 监控和比较多个指标或状态 | 主要决策是什么，异常如何下钻，图表是否有可信时间范围与单位 |
| 文档或内容编辑 | 阅读、组织和持续写作 | 文档层级、编辑状态、保存与历史能否被理解 |

这些结构可以局部组合，但每增加一个侧栏、工具栏或面板都应说明它支持哪个任务。复杂产品也不必把所有入口放在第一屏。

## 对象、层级与密度

用真实长度、数量和状态的数据设计。短占位符会掩盖换行、溢出、缺失值、同名项目和长列表的问题。区分当前对象、选中对象、正在操作的对象和后台任务，避免用同一高亮同时表达多种状态。

高密度适合熟练用户连续比较，不等于缩小所有字与点击区域。把常用信息放近，把详细说明留在可到达的位置；通过分组、对齐、标题和有限强调建立层次。

低密度适合首次理解、创作展示或明确的单任务，但也不能把核心内容拆到过多滚动和跳转中。界面需要证明的是任务顺畅，而不是填满或留空某个比例。

## 从结构到实现

先选稳定的信息架构与区域关系，再定义 tokens、基础组件、可复用交互和领域组件。颜色、间距、圆角等值从项目现有系统出发；示例里的具体数值是起点，不能取代实际屏幕检查。

关键状态包括正常、空、加载、错误、权限、完成与恢复，按本次任务的重要性覆盖。为每个状态说明用户能做什么，避免只有一张理想数据截图。

已经被用户认可的页面区域、导航和信息层级构成实施依据。后续实现改变它们时，说明变化和影响；不能因为原型文件不是生产代码就忽略其设计决定。
