# 关键交互模式

按任务选择要检查的模式，不要求每个原型都包含全套组件。

| 模式 | 应让用户理解什么 | 需要观察的边界 |
| --- | --- | --- |
| 导航与命令入口 | 我在哪里、有哪些对象、怎样返回 | 深链接、返回、权限变化、键盘、当前页与选中项区别 |
| 搜索与筛选 | 当前范围、筛选条件、结果依据 | 无结果、慢响应、组合条件、清除和返回时状态 |
| 表格与列表 | 可比较的信息、可选择的对象、批量操作影响 | 长文本、缺失值、排序、分页/虚拟列表、部分失败 |
| 表单与配置 | 输入含义、必要信息、保存与取消结果 | 校验位置、保留输入、重复提交、离开时未保存内容 |
| 详情与编辑 | 正在查看和修改的对象、修改是否生效 | 并发变化、撤销、历史、保存中与失败、权限 |
| 弹层与抽屉 | 这次临时操作的范围和退出方式 | 焦点进入/返回、键盘退出、滚动、遮挡、移动端空间 |
| 长任务与后台操作 | 已接收、进行中、完成或失败，以及可以做什么 | 超时、取消、重试、部分结果；进度不可测时不伪造百分比 |
| 确认与恢复 | 操作影响和实际恢复路径 | 不可逆操作、默认选择、重复执行、撤销是否真实存在 |
| 消息与反馈 | 哪个对象发生了什么、下一步是什么 | 全局提示会否丢失，重要错误是否只短暂闪现 |

## 反馈要对应实际状态

加载占位、乐观更新、通知和进度都有适用条件。仅在能处理失败、回滚与重复操作时使用乐观更新；未知结果不能显示成成功。

原型使用模拟数据时，可以演示状态转换，但明确模拟范围。生产实施需验证真实请求、错误与持久化，不能从原型按钮有动画推断业务已工作。

## 输入与可访问性

检查键盘路径、焦点可见性、控件名称、触摸目标和阅读顺序。需要悬停才能发现的重要操作应有其他入口；拖拽、快捷键和手势也应有适当替代方式。

采用项目现有组件时，优先保持其交互契约。新做样式不能破坏控件的语义和键盘行为。依赖浏览器实际行为的内容在浏览器中观察，而不是只检查 CSS。
