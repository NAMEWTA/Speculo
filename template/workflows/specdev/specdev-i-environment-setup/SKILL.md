# 部署环境初始化

先确认本次要准备的是发起操作的本机、远程服务器还是某个项目。这里负责控制端准备；远端接入使用 [服务器接入](../specdev-s-server-connect/SKILL.md)，主机系统变更使用 [主机维护](../specdev-h-host-manage/SKILL.md)。

读取项目已有部署脚本、基础设施配置和环境说明。识别实际需要的 SSH、Git、容器/云 CLI、运行时与权限，检查版本和可用性；不要求所有主机都安装 Node 或一整套工具。

已有工具与账号配置直接复用。仅为本次任务确实需要的缺口安装或调整，沿用户授权与正常包管理方式执行。区分已发现命令、认证可用和已经实际完成操作，不把工具存在写成部署能力已验证。

连接方式和凭据只保存引用，例如 SSH config 别名、agent、密钥路径或 secrets 服务名称；不把 token、密码和私钥正文写进知识文档。权限不足说明具体缺口，不绕过系统访问控制。

优先更新已有环境记录。没有时，在项目根 `.agents/speculo/.speculo/environments/` 按实际目标保存说明；只准备本机时不虚构服务器、账号、部署目录或运行实例。

记录今后需要的工具、配置位置、使用入口与尚未满足的条件即可，不生成身份注册账本、空状态根或安装协议。需要把本机当成部署目标时明确记录该目标及其应用/数据位置。

交付可用的控制端、真实检查结果和下一步。用户已要求完整部署时继续接入和部署，不在工具检查完成后提前停止。
