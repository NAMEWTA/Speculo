# 性能调查与可比较测量

先明确用户关心的操作与结果，例如打开工作区、搜索、渲染列表、构建或处理请求。定义输入规模与实际测量边界，不从局部函数快就推断整体快。

记录运行版本、配置、硬件/环境、冷暖缓存、并发、输入和计时方式。保留原始样本与离散情况，选择能反映需求的统计；单次最快值不能代表稳定性能。

沿端到端路径定位 CPU、I/O、网络、锁、内存、渲染或等待成本。使用适合环境的 profiler、trace 或计时，注明观察工具本身可能带来的影响。

候选优化需要解释机制、预期受益的工作量、正确性风险与额外维护成本。缓存要说明失效与内存，批处理要说明延迟与失败语义，并发要说明资源竞争，惰性加载要说明首次使用代价。

对比前后使用相同场景与可解释环境，确认功能和结果一致。局部改善可能被其他瓶颈抵消，收益不足或证据不稳定时如实报告。

基线调查、优化建议与已经实现的加速分别说明。用户只要求报告时不改生产代码；要求实施时将测量入口与接受条件交给实际改动，并复测受影响的场景。
