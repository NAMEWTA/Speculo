# 复现与区分性实验

选择能捕获原症状的最小反馈，而不是最容易变红的命令。

| 情况 | 可用方法 | 需要避免的误判 |
|---|---|---|
| 稳定逻辑错误 | 针对公共行为的回归测试或最小输入 | 内部断言失败却未覆盖用户症状 |
| API、CLI 或集成 | 精确请求、参数、响应与副作用核对 | 只有退出码，没有检查业务结果 |
| UI 状态问题 | 同页面、状态、输入与视口的实际操作 | 原型截图代替生产页面，或只查事件绑定 |
| 间歇并发 | 明确同步点、受控调度、重复率与资源观测 | 无依据的 sleep、扩大超时或全局串行 |
| 历史回归 | 固定版本的差分或 bisect | 工作区和依赖变化污染版本比较 |
| 一次性事故 | 时间线、部署差异、日志、追踪和数据快照 | 将一个合理故事写成已证实根因 |

最小化时逐步去掉输入、环境和步骤，每次检查是否仍捕获相同问题。复杂环境无法完全最小化时，说明剩余依赖与已排除项即可，不把“必须最小”变成阻塞调查的形式门。

每个候选原因先写预期观察，选能区分它与主要替代解释的实验。优先使用已有 debugger、测试夹具和定向日志；性能问题测量端到端与热点，注意采样开销。

对临时修改保留原内容或可还原 diff，使用清楚的范围与标记。测试变异只有实际执行到变异且因目标断言失败才说明敏感性；编译失败或测试未运行没有同等含义。

清理探针后核对原始场景与工作区。无法重现时交付最有依据的假设、反证与下一步，不把静态代码推断冒充实验确认。
