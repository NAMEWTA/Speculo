# 主机环境维护

固定本次目标服务器与所需结果，读取现有环境说明及实际观测。主机系统、共享服务和单项目部署分别识别，避免一个项目请求被扩大成整机治理。

## 调查与选择动作

按实际问题检查系统资源、磁盘、进程、容器、运行时、网络、入口服务或权限。把配置声明、正在运行的状态和历史检查分开；未知占用先辨明，不用进程名猜业务归属。

维护 Docker、代理、反向代理、证书、防火墙、语言环境或服务管理时，查看当前消费者与已有配置。重启或切换共享入口之前知道会影响哪些项目、连接和定时任务。

清理资源先区分可重建缓存、未使用镜像、日志、活跃容器和业务数据。依据实际引用与保留要求选择范围，不能把空间大的目录自动当作可删垃圾。

## 执行与恢复

沿现有系统管理方式执行本次授权范围内的修改，保留需要恢复的配置和版本。新增破坏性效果或超出已明确范围的影响要先说明；普通已授权准备工作不逐步重复确认。

先验证配置，再在适当范围切换或重启；关注远程连接是否会被自身操作中断。失败时核对实际落地变化与服务状态，使用适用恢复方案，不以重建任务掩盖未知结果。

有关部署布局、共享依赖和数据边界时阅读 [环境与运维参考](../references/operations.md)。主机检查通过后仍需验证受影响项目的实际业务路径。

## 交付

报告目标、具体修改、受影响消费者、实际检查和剩余问题。更新已有环境说明中的可复用事实；有服务端 README 时同步必要变化，不强制生成两套文档与摘要账本。

多环境总览可交 [资产盘点](../specdev-v-inventory-view/SKILL.md)，单项目变更继续 [项目部署](../specdev-d-project-deploy/SKILL.md)。
