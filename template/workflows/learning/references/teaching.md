# 讲解、练习与学习证据

在需要解释概念、组织课程、判读作答或安排复习时使用。表达难度、知识深度与学习者掌握程度分别判断。

## 先确定学习意图

“教我完整理解”需要连贯讲解；“这个词什么意思”可以短答；“直接替我研究”可以给出研究结果。只有用户希望练习或检查理解时才留题目让其作答。已经给出的答案和偏好直接沿用，不用重复问诊拖延教学。

选一个能代表目标的情境，说明为什么要学、学会后能做什么、已有知识如何连接新知识。术语第一次出现时解释，在后文保持同一称呼。类比先帮助建立直觉，再交代与真实机制不同的地方。

## 深度与表达

讲人话并不等于略去核心机制。可以从一个具体实例进入，逐层展开因果关系、运行步骤和必要细节，最后用反例或改变条件说明适用边界。避免只给名词清单，也避免先抛出一串陌生术语再让用户自行拼接。

优先采用短而完整的句子，一个段落解决一个问题。保留准确的技术名称，在其附近说明含义。图、公式、代码、表格都以是否能澄清当前问题为依据，不要求每节课固定配齐。

| 要解释的内容 | 有用的展开方式 |
| --- | --- |
| 概念与相似概念的区别 | 共同点、决定性差异、边界案例 |
| 一个系统为何这样运行 | 输入、状态变化、输出、失败路径及设计取舍 |
| 一项操作如何完成 | 真实环境、可运行示例、观察结果、常见偏差 |
| 一条规则为什么成立 | 假设、推理或证据、反例、何时不适用 |
| 不同方案如何选择 | 同一具体场景下的收益、代价和转向条件 |

对于源码或工具，绑定实际版本与入口。把真实运行结果、源码推断、教学简化区分开；简化示例不能冒充生产实现。

## 练习与反馈

根据目标选择解释、预测结果、找错、实现、比较或迁移题。题量服从信息需求；一题已经暴露关键误解，就先解决它，不为了完成固定问卷继续提问。

保留学习者原始作答，再给出反馈。指出具体哪句话或哪一步支持判断，解释正确部分、遗漏、错误原因和如何改进。不要只打分，也不要用润色后的答案替代原答，造成“原本就会”的假象。

当答案含糊时，用一个有区分度的追问区分概念混淆、表达不清、记忆缺口和操作失误。材料未覆盖不等于学习者不会；学习者没有提交答案不等于答错。

## 复习与掌握程度

即时复述、提示后完成、独立应用和延迟迁移是不同证据。记录实际观察到的层级，不由“看完课程”“回答过一次”推断长期掌握。

复习围绕已暴露的薄弱点安排新情境，先尝试提取，再给提示和解释。间隔按用户时间与表现调整；没有用户授权，不自行建立通知或日程。若用户要求长期学习计划，可在同一学习记录中留下下一次检验的目标，而不是维护多套状态账本。

## 留下什么

通常保留目标、资料版本、关键解释、原始答案与反馈、下一步即可。完整讲义或代码已有独立文件时引用它。反复有用的概念模型和误区可以进入知识笔记；一次性的长对话无需逐字复制。
