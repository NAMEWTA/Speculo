# 完整课程讲解

读取用户当前问题、已有背景与相关资料，直接给出能独立理解的一课。没有完整课程计划也可以授课；只有缺失的信息会实质改变讲解时才询问。

## 组织讲解

先交代这个主题解决什么问题、在整体中处于哪里，再解释核心概念与运行机制。用贯穿的例子连接各部分，让读者能跟着一次输入、推理或操作看到结果。

逐步引入术语，清晰区分相邻概念。类比后补上精确定义及不适用处；简化表达不能删去重要条件、反例或不确定性。需要具体表达方法时阅读 [教学方法](../references/teaching.md)。

主题适合时，展示结构、数据流、状态变化或因果关系。工程案例说明真实责任边界与失败路径，数学与理论主题通过证明、反例或模型假设深化。图示、公式和代码服务理解，不作为固定配额。

## 深度与应用

解释为什么这样设计或成立、替代方式会改变什么，以及什么时候不适用。把盲区通过具体情境讲清：直觉会在哪里出错、如何识别、如何验证。进一步深入时使用 [探究参考](../references/inquiry.md)。

明确用户材料、一手来源、自己的推断与教学假设。外部 API、版本或易变事实按当前资料核实，不伪造实验、源码执行或文献出处。

## 交付

范围与时长按用户请求、内容难度和实际需要安排，不机械固定为一节若干分钟。用户要完整讲解就先完成讲解，不把正文变成必须逐题回答的考试。

需要保存时更新当前主题笔记，引用实际来源；新的独立讲义再拆文件。学习者可主动选择 [作业](../learning-h-homework/SKILL.md)、[问答](../learning-q-question/SKILL.md) 或 [延迟复习](../learning-r-review/SKILL.md)。讲完不代表已经掌握。
