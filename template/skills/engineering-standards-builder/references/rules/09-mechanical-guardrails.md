# 可验证的工程约束

仅在项目证据支持且用户所选范围需要时应用。先检查现有 lint、test、pre-commit、CI 是否已有规则且真正接入；已有检查失效优先修复接入，不复制禁令到更多文档。

TypeScript 深模块可用项目现有 dependency-cruiser 或等价工具表达公开入口、私有实现、依赖方向与无环约束。先观察消费者和既有 exports/API；不能统一强制所有项目采用某种目录布局。测试可以通过公共入口验证行为，内部测试是否保留按实际维护收益决定。

候选机械约束必须有通过→故意违规失败→恢复后通过的证据，并证明违规落地、检查命中了实际文件。pre-commit 只作为项目已有/明确选择的执行点，不默认安装 Husky、格式化器或依赖，不静默修改 CI。新增安装、脚本或配置属于独立实现写集，由调用方决定。

生成的工程 Skill 只引用实际存在的命令和约束；尚未实现的建议单列，不伪装成已生效规则。
