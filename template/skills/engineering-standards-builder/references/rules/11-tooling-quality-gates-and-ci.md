# 工具链、质量门禁与 CI

## 稳定职责

每个项目模块应通过现有构建系统提供稳定职责，具体命令按生态决定：

```text
format / format-check
lint / static-analysis
compile / typecheck
unit-test
integration-test
build / package
security / dependency-audit
check
```

这些是职责分类，不是跨语言命令名。生成规范必须记录各模块构建系统中的真实命令、任务或生命周期。

## 门禁来源

按可信度：

1. CI 实际执行；
2. package/build 文件定义；
3. Agent/贡献文档；
4. 本地约定；
5. 用户确认的新目标。

脚本存在但 CI 不执行时，记录为本地工具而非合并门禁。

## 格式与静态检查

- 机械风格由 formatter 决定，review 不重复争论；
- Lint/静态分析聚焦缺陷、API 和边界；
- 类型感知或全程序检查的性能成本按模块评估；
- 规则禁用最小化、解释 WHY，并有删除条件；
- 生成代码采用独立配置或排除，不能与手写代码混淆。

## CI 设计

- 锁定工具链和依赖解析；
- 缓存不得影响正确性；
- 快速、独立检查可并行；
- 失败输出足以复现；
- 慢测试和平台矩阵按风险分层；
- 合并门禁不依赖开发者本地隐式状态；
- 代码生成结果若需提交，CI 验证 freshness；
- 任何自动修复在 CI 中默认只检查，不静默改写提交。

## 禁止绕过

不得为获得绿色状态而：

- 删除或长期跳过失败测试；
- 文件级关闭核心安全、并发、类型或生命周期规则；
- 全局放宽编译配置解决单个文件；
- 排除关键模块以提高覆盖率；
- 忽略生成、打包或发布失败；
- 将失败命令改成始终退出 0。

## 新门禁采用

存量仓库先测量基线，再采用：

- 仅新代码/变更文件；
- 错误数量 Ratchet；
- 模块分阶段；
- 明确到期的临时 allowlist。
