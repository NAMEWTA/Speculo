# 安全、配置与数据

## 外部输入

在信任边界验证并标准化：

- HTTP/RPC/消息/CLI 输入；
- 文件路径、文件类型和上传内容；
- URL、重定向和来源；
- 环境变量和配置文件；
- 数据库、缓存和第三方响应；
- 反序列化、模板和富文本。

验证结果转换为内部可信模型，避免在业务代码中反复使用原始动态数据。

## 注入与输出

- SQL、命令和查询使用参数化接口；
- HTML/模板输出按上下文转义；
- 原始 HTML、动态代码、反射和 shell 仅在受控边界使用；
- 路径在受控根内解析并防止遍历、symlink 越界；
- 前端可见性不能替代服务端授权；
- 日志和错误响应不包含秘密或过量个人信息。

## 配置

- 在应用启动/模块边界读取、验证、标准化配置；
- 业务代码依赖只读配置对象而不是随处读取环境变量；
- 环境差异由外部配置表达，不复制业务逻辑；
- 默认值必须安全且可观察；
- 配置来源、优先级和必填项写入项目规范；
- secret 只通过批准的 secret provider/环境注入，不提交仓库。

## 数据与迁移

- schema、序列化格式和事件版本属于兼容合同；
- 迁移可重入、可观察、必要时可回滚；
- 破坏性变化采用 expand/migrate/contract 或项目确认策略；
- 数据保留、删除、审计和隐私规则明确；
- 幂等性键、事务边界和一致性模型按业务风险定义。

## 依赖安全

新依赖评估维护状态、许可证、供应链、体积、平台和替代方案。使用仓库已有审计工具；不得凭 Builder 擅自引入安全产品。
