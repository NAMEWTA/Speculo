# 通用文档与注释

## 注释解释 WHY

注释用于解释代码无法自证的内容：

- 兼容性、协议与平台限制；
- 非直观的性能或安全权衡；
- 数据迁移和历史原因；
- 资源生命周期或并发不变量；
- 临时例外及删除条件。

不逐行翻译实现，不用注释掩盖模糊命名和职责混合。

## 公共合同文档

公共 API、包、模块、crate、命令、配置和扩展点按语言生态使用 JSDoc/TSDoc、Javadoc、Go doc 或 rustdoc。至少说明：

- 用途和适用边界；
- 输入、输出、失败与副作用；
- 生命周期、线程/并发或取消要求；
- 兼容性和示例；
- 安全敏感约束。

内部显而易见的 getter/setter 不需要重复性文档。

## 架构文档

以下变化应同步文档或 ADR：

- 模块边界和依赖方向；
- public API 或协议；
- 数据模型、迁移和事件；
- 部署拓扑和运行环境；
- 质量门禁与支持版本；
- 重大例外和阶段性目标。

## TODO

TODO 必须包含可行动信息：

```text
TODO(owner-or-issue): 原因；删除/完成条件
```

禁止把无期限风险转为无上下文 TODO。
