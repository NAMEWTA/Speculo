# 性能、可观测性与国际化

## 性能

- 优化前先确认用户/系统指标和测量方法；
- 优先减少算法复杂度、I/O 次数、网络往返和大型复制；
- 大集合采用分页、流式、窗口化或虚拟化；
- 缓存定义键、容量、淘汰、失效、一致性和隔离；
- 并发度、队列、重试和批量大小有上限；
- 非直观优化附 WHY、基准或回归测试；
- 不因微优化破坏清晰 API 和正确性。

## 可观测性

- 日志、指标和 trace 使用稳定字段和关联 ID；
- 日志级别表达可操作性，不重复记录同一错误；
- 不记录秘密和不必要个人数据；
- 异步任务、队列、重试、缓存和外部调用有成功/失败/延迟信号；
- health/readiness 反映真实依赖与启动状态；
- 采样、基数和保留策略避免成本失控。

## 国际化

仅在项目有用户多语言或区域化需求时生成：

- 用户可见文本进入项目既有 i18n 系统；
- 文案键按领域命名；
- 插值使用具名参数；
- 不用字符串拼接构造自然语言；
- 日期、数字、货币、时区、排序和复数使用区域 API；
- 日志/错误码与用户文案分离；
- UI 考虑文本扩展、RTL 和可访问性。

## 验证

根据项目事实选择 profiler、benchmark、bundle check、load test、指标查询或 review 证据，不生成不存在的门禁命令。
