# React 与前端规范

仅在项目实际使用 React 或类似组件框架时生成本模块。

## 组件

- Props 明确表达输入，渲染尽量纯粹。
- 数据获取、业务状态编排、领域交互和视觉展示按复杂度拆分。
- 组件使用具体领域名称，避免 `CommonModal`、`GenericPanel`。
- 组件文件命名由仓库事实或用户问答确认。

## Props 与 Hook

- Props 类型使用项目统一命名，如 `XxxProps`。
- 布尔 Props 使用 `is`、`has`、`can`、`should`。
- 事件 Props 使用 `onXxx`。
- 复杂互斥状态使用联合类型，不用多个布尔值构造隐式状态机。
- 自定义 Hook 以 `use` 开头，一个 Hook 一个可命名职责。
- Effect 依赖完整，创建资源时返回清理函数。

## 状态和 Effect

- 状态尽量靠近使用位置。
- Store 按领域切片，不创建单一巨型 Store。
- 派生数据优先计算，不重复存储。
- Effect 用于与外部系统同步，不替代普通计算。
- 异步 Effect 考虑取消、竞态和过期响应。

## 性能与可访问性

- 不滥用 `memo`、`useMemo`、`useCallback`。
- 优化基于测量或已识别瓶颈。
- 长列表使用虚拟化，高频事件使用调度或节流。
- 使用语义化 HTML，交互支持键盘，图标按钮有可访问名称。
- 不以颜色作为唯一状态表达。

## 浏览器边界

验证 URL、消息、Storage 和第三方脚本输入；不把秘密放入前端 Bundle；不直接导入 Node 专属模块，除非平台提供受控桥接。
