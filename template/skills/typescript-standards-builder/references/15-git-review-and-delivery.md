# Git、代码评审与交付

## 提交与 PR

- 一个提交和 PR 聚焦一个逻辑主题。
- 不混入无关全仓库格式化。
- 缺陷修复提供回归测试。
- UI 变化提供截图或录屏。
- 说明背景、方案、风险和验证方式。
- 评估跨平台、性能、安全和兼容性影响。

提交格式可采用仓库已有约定；没有约定时推荐 Conventional Commits。

## 评审优先级

1. 正确性、安全和数据损坏。
2. 外部输入和类型边界。
3. 资源泄漏、竞态、取消和错误处理。
4. 架构边界、循环依赖和公共 API。
5. 测试缺口。
6. 文件职责、大小和命名。
7. 纯风格建议。

每条问题包含位置、风险、触发条件和修复方向。不要把个人偏好描述成缺陷。

## 门禁

合并前执行项目确认的格式、Lint、类型、测试和构建检查。无法执行的项目必须明确报告，不得声称已通过。
