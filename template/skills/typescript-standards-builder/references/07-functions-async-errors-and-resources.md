# 函数、异步、错误与资源生命周期

## 函数职责

函数只处理一个可命名职责和一个抽象层级。项目规范可设置函数行数、嵌套和参数数量的软预算，但不得为满足数字做无意义拆分。

- 使用 Guard Clause 减少嵌套。
- 长参数列表和布尔参数改为具名参数对象。
- 分离解析、验证、领域决策、I/O 和流程编排。
- 纯逻辑不读取隐藏全局状态，不修改输入。

## Promise 必须有归宿

所有 Promise 必须被 `await`、`return`、显式收集，或用 `void` 明确脱离当前流程并自行处理错误。

只有互相独立的任务才使用 `Promise.all`。大型输入不得无界并发。

## 取消、超时与重试

网络、子进程、文件监听、Worker 和长任务应考虑：

- `AbortSignal`。
- 明确超时。
- 清理路径。
- 可识别取消错误。
- 超时后底层资源是否真正停止。

重试必须定义最大次数、退避、抖动、可重试错误和幂等性。

## 错误

不得吞掉异常。错误应包含操作上下文并保留 `cause`。

调用方需要分支处理的错误使用具名错误类、结构化 `code`、`Result<T, E>` 或可辨识联合，不匹配错误消息字符串。

`catch` 值视为 `unknown`，先收窄再处理。

## 资源清理

事件监听器、Timer、文件句柄、Socket、数据库连接、Worker、子进程、`AbortController` 和 React Effect 订阅必须有明确生命周期。

创建资源的模块通常负责定义或暴露清理方式，可返回清理函数或实现 `dispose()`。
