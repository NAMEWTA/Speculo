# 落地、例外与迁移

## 不机械复制

项目规范只生成实际适用的内容：

- 普通 Web 项目不生成 Electron 主进程规则。
- 非 React 项目不生成 Hook 和组件约定。
- 已使用 Biome/Oxc 的项目不强行切换到 ESLint/Prettier。
- 生成器管理的目录保留生成器约定。
- 通用行数阈值必须结合仓库实际调整。

复制的是目标：边界清晰、职责具体、类型严格、质量自动化、修改可验证。

## 例外

例外必须：

1. 有具体技术原因。
2. 范围尽可能小。
3. 在代码、配置、决策记录或 PR 中说明。
4. 不破坏核心安全和类型边界。
5. 临时例外有负责人、退出条件和任务编号。
6. 经评审确认。

## 遗留项目

推荐阶段：

### 1. 建立事实和命令

固定包管理器和锁文件，建立稳定 `format:check`、`lint`、`typecheck`、`test`、`build`。

### 2. 阻止新增债务

- 新文件遵守具体命名和大小预算。
- 新 API 不传播 `any`。
- 新边界输入必须验证。
- 缺陷修复补回归测试。

### 3. 触及治理

修改旧文件时降低复杂度、拆出纯逻辑、补测试、清理循环依赖和万能工具文件。

### 4. 专项迁移

分模块开启严格选项、迁移目录、引入项目引用和依赖边界检查。

## Ratchet 指标

可跟踪：

- 超限文件数量不增加。
- `any` 和 `@ts-ignore` 不增加。
- 循环依赖不增加。
- 跳过测试不增加。
- Lint 警告基线只下降。

## 大规模重命名

仅在用户明确确认时进行，使用独立变更，不混入功能修改，并验证大小写敏感文件系统、导入、测试、文档和构建。
