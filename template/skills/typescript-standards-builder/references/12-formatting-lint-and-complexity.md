# 格式化、Lint 与复杂度

## 工具统一风格

格式由仓库选定的 Prettier、Oxfmt、Biome 或其他工具自动完成。代码评审不争论工具已经确定的空格、换行和引号。

具体选项必须从现有配置或用户问答生成，不机械复制某个项目的完整格式配置。

## 文件大小预算

这是固定默认原则：普通 TypeScript、React、测试和脚本使用不同预算。

通用起点：

| 文件类型 | 可作为初始推荐的软上限 |
|---|---:|
| 普通 `.ts` | 300 行 |
| React `.tsx` | 400 行 |
| 测试 | 600～800 行 |
| 构建或生成脚本 | 600 行 |
| 函数 | 40～60 行 |

生成项目规范时必须结合仓库实际分位数和用户选择调整。数字是审查触发器，不是机械裁决。

超限时检查：

- 是否混合多个职责或抽象层级。
- 分支、状态和依赖是否过多。
- 是否可分离解析、验证、I/O、领域规则或 UI 展示。
- 拆分后能否得到具体文件名。

禁止为了满足行数把代码拆进 `helpers.ts`。

## Ratchet

历史超限文件不要求一次性重写，但：

- 新变更不得继续无边界增长。
- 每次触及时应提取一项明确职责或降低复杂度。
- CI 可只阻止新增超限，而不一次阻塞全部历史文件。

## Lint 覆盖

至少覆盖：

- 未使用变量和导入。
- 浮动 Promise。
- 不可达和重复分支。
- React Hooks 规则。
- 显式 `any` 和不安全断言。
- 类型导入一致性。
- Switch 穷尽检查。
- 循环依赖和禁止跨层导入。
- 文件大小、嵌套和复杂度。

## 禁用规则

规则禁用必须精确到最小范围、指明规则名、解释 WHY，并在临时例外中附删除条件。禁止文件级关闭核心类型、Hooks、Promise 或安全规则来掩盖问题。
