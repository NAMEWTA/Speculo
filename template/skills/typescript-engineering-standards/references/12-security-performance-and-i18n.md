# 安全、性能与国际化

## 输入安全

所有外部输入必须验证，包括 API、IPC、消息、配置、文件、URL 和用户输入。

- 路径防止目录穿越。
- SQL 使用参数化查询。
- Shell 使用参数数组并正确转义。
- HTML 默认转义，谨慎使用原始 HTML。
- URL、重定向和文件类型需要校验。
- 跨窗口、跨进程消息校验来源和结构。

## 敏感信息

禁止：

- 日志记录密码、Token、Cookie、私钥。
- 将秘密打包到浏览器代码。
- 提交 `.env`、证书或生产配置。
- 向最终用户泄露内部堆栈、路径和未脱敏请求。
- 把用户输入直接作为命令、查询或文件路径执行。

日志应使用结构化字段并在边界脱敏。

## 权限

- 默认最小权限。
- 权限判断集中在策略或 Guard 中。
- UI 隐藏按钮不能替代服务端鉴权。
- 高风险操作有确认、审计和幂等保护。
- 不依赖客户端可篡改字段作最终安全决策。

## 性能原则

- 优化以前先测量。
- 优先改进算法复杂度、I/O 次数和数据复制。
- 大文件、日志和列表使用流式、分页、窗口化或虚拟化。
- 避免热路径重复解析配置、创建正则、序列化大型对象或读取磁盘。
- 定时器、监听器、队列和缓存必须有上限和清理。

## 缓存

缓存需要明确：

- 键和命名空间。
- 容量上限。
- 淘汰策略。
- 过期和主动失效。
- 一致性要求。
- 是否缓存错误或空结果。

非直观优化应有基准、回归测试或简短原因说明。

## 国际化

有多语言需求时：

- 用户可见文本不散落为硬编码字符串。
- 文案键按领域语义命名，不按屏幕位置命名。
- 插值使用具名参数。
- 不拼接自然语言句子。
- 日期、数字、货币和复数使用国际化 API。
- 用户提示和开发日志分离。
- CI 检查缺失键、未使用键和占位符不一致。
