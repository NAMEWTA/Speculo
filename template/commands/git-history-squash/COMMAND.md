# 整理 Git 历史

核对目标仓库、分支、起止提交和最终要保留的内容，范围已有明确说明就直接使用。先检查工作区和提交拓扑；未提交内容或合并关系影响结果时先解决该具体问题。

展示将替换的提交范围、最终提交信息和受影响的引用。仅讨论方案或要求预览时保持只读；实际改写沿用当前会话覆盖该范围的授权。

改写前记录旧 HEAD，并建立可恢复的备份引用。再次核对目标未变化，选择适合当前拓扑的 Git 操作；保留用户未纳入范围的提交与工作区编辑。

完成后比较旧、新最终 tree，确认保留的内容一致、目标区间已收敛且备份可用。涉及子仓库时逐个核对提交及父仓库引用，分别记录结果。

远端更新只在对应目标已获授权时进行，使用单一明确 refspec 和 `--force-with-lease=<ref>:<old-sha>`。远端已变化时停止该推送并核对新历史，不改用无条件强推。

报告旧、新提交、备份引用、实际远端结果和恢复方法。失败或部分成功保留现状与证据，备份不自动删除；需要保存恢复说明时按 [持久化](../../references/memory.md) 写入现有记录。
