# Git 仓库审计

从用户指定的仓库、分支、时间、作者或路径确定范围，固定本次读取的提交 SHA。默认使用本地历史；未读取远端时说明覆盖边界，不为了审计自动改变 refs。

## 分析依据

先看项目入口、目录与实际 diff，再判断功能变化、缺陷修复、热点路径及演进。需要统计时明确身份合并、机器人、merge、rename、二进制和生成物的处理；浅克隆、缺失分支或时间范围不完整应单独说明。

抽查重要提交的代码及调用方，把“新增某能力”等结论落实到实际变更。提交数量、行数和活跃时间只反映记录活动，不能单独认证质量、效率或个人能力。

## 结果

按用户关心的问题给出主要发现，附固定 SHA、路径和必要复核命令。区分原始指标、从差异推导的判断和无法确认的部分。统计汇总应能由样本与范围解释，缺失数据不填零。

本命令保持源码、工作区、Git 引用和配置不变。默认在会话返回；用户要文件时按 [持久化](../../references/memory.md) 保存完整报告。审计发现的问题不自动变成代码修改或远端 issue。
