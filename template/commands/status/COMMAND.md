# 查看进度

按用户指定项目、领域或主题定位已有记录和安装入口。未给范围时从当前项目的活动工作开始；不默认读取整棵历史、全部知识或远端。

## 读什么

软件交付看相关 release、旧 change、Git 和已记录的交付结果；学习看目标、课程、真实回答与复习记录；媒体看作品、工程、渲染或发布回执；Person 看问题、依据、待验证假设与后续行动。部署盘点优先看环境说明和最近观测，必要时可参考 [inventory-view](../../workflows/specdev/specdev-v-inventory-view/SKILL.md)。

需要解释某种任务时按对应 Work 的语义读取少量来源，不重新运行初始化、校验状态机或执行业务操作。安装缺失与业务资料缺失分别说明。

## 怎样判断

核对记录是否对应当前文件、版本或实际回执。完成、部分完成、待用户明确要求的验收和未知分别表达；没有实际远端观测就不说服务实时健康。

同名不同对象不合并；缺失和冲突标为未知，不填零。时间使用真实来源，不以文件 mtime 推断工作者已经退出。一个领域有缺口时继续独立可读的部分。

## 返回结果

给出当前结果、必要证据位置、阻塞和具体可继续的下一步，按领域保留不同指标含义。默认在会话返回，不写新状态、不修复记录或移动归档。用户要求保存摘要时按 [持久化](../../references/memory.md) 更新已有记录；保存摘要不授权部署或其他后续动作。
