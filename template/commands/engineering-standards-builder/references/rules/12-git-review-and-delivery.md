# Git、评审与交付

## 变更边界

- 提交和 PR 聚焦一个逻辑主题；
- 不混入无关全仓格式化或自动生成差异；
- 重构与行为变化在可行时分离；
- public API、schema、协议和迁移变化显式标记；
- 生成文件变化可追溯到生成命令和源文件。

## PR 说明

至少包含：

```text
背景/问题
方案与关键权衡
影响模块与兼容性
风险与回滚
验证命令和结果
截图/录屏（UI 变化）
迁移/发布注意事项
```

提交格式遵循仓库事实；无约定时可建议 Conventional Commits，但不是跨项目硬规则。

## 评审重点

按风险检查：

- 需求和边界是否正确；
- 错误、取消、资源和并发路径；
- 安全、权限、数据与隐私；
- public API 和向后兼容；
- 测试层级是否匹配风险；
- 依赖方向和生成代码；
- 性能、可观测性、国际化和可访问性；
- 部署、迁移、回滚与跨平台。

## 交付

- 发布产物从可复现构建产生；
- 版本、changelog 和兼容策略遵循项目事实；
- 数据/配置迁移有顺序与回滚；
- feature flag 有所有者和清理日期；
- 发布后监控和失败恢复责任明确。
