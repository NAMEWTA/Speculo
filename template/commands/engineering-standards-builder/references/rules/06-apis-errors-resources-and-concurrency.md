# 通用 API、错误、资源与并发

## API 合同

- 输入、输出、失败、取消、超时和副作用必须可理解；
- 外部输入在边界转换为内部可信模型；
- 使用类型、schema 或显式验证表达非法状态；
- 布尔参数超过一个或存在互斥组合时，优先使用具名配置/枚举/领域类型；
- 不用日志替代返回错误或失败状态；
- public API 的错误语义与兼容性必须稳定。

## 错误处理

- 错误增加有用上下文但保留原始 cause；
- 只在能够恢复、映射、补偿或增加边界上下文时捕获；
- 用户信息、运维日志和机器错误码分离；
- 不泄露秘密、内部路径、SQL、Token 或敏感数据；
- retry 必须限定可重试错误、次数、退避、抖动和幂等性；
- panic/exception/process exit 只允许在对应语言和应用边界定义的位置。

## 资源生命周期

任何资源都要回答：

```text
谁创建？
谁拥有？
何时可用？
如何取消/关闭？
失败时如何清理？
重复关闭是否安全？
```

资源包括文件、连接、事务、锁、线程、goroutine、异步任务、timer、监听器、订阅、子进程、缓存和临时目录。

## 并发

- 并发任务必须有所有者和终止条件；
- 传播取消、截止时间和 backpressure；
- 共享可变状态需要同步策略；
- 不启动无法观察、无法等待或无法清理的后台任务；
- 处理重复、乱序、过期响应和部分失败；
- 语言适配器决定具体 primitive，不跨语言复制模式。

## 验证

至少使用一种：

- 类型/编译检查；
- 资源泄漏或并发测试；
- race detector、sanitizer、静态分析；
- 超时/取消/失败路径测试；
- 精确 review checklist。
