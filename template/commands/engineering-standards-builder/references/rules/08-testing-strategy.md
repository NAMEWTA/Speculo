# 通用测试策略

## 按风险选择层级

- **单元测试**：纯领域逻辑、边界值、错误分支；
- **组件/切片测试**：框架组件或单层集成；
- **集成测试**：数据库、消息、文件系统、网络、容器或模块协作；
- **契约测试**：公共 API、事件、schema、SDK/服务消费者；
- **端到端测试**：关键用户和交付路径；
- **属性/Fuzz/并发测试**：解析器、协议、算法和竞争风险；
- **基准/性能回归**：已识别性能合同。

测试布局由语言生态、构建系统和仓库事实决定；通用层只规定测试责任，不规定文件后缀、共置方式或 source set。具体位置全部由对应语言适配器给出。

## 行为优先

- 测试公开行为和可观察结果；
- 避免绑定私有实现、内部调用顺序和脆弱 snapshot；
- 缺陷修复优先提供可复现回归测试；
- 测试失败信息能定位输入、期望和实际结果；
- mock 只隔离真正外部或不稳定边界；
- 核心集成风险使用真实实现、容器或轻量替代；
- 时间、随机、网络和并发测试需可控且可重复。

## 测试数据

- 使用 builder/factory/fixture 表达意图；
- 不复制大段无关数据；
- 敏感生产数据不得进入测试仓库；
- 测试拥有并清理创建的文件、连接、容器和进程；
- 并行测试不得共享无保护状态。

## 覆盖率

覆盖率是发现盲区的信号，不是质量代理。门槛应按模块风险、存量基线与新增代码 Ratchet 设定，不通过排除关键文件来获取数字。

## CI

项目规范写明：

- 本地快速集合；
- PR 必跑集合；
- 主分支/夜间慢测试；
- flaky test 处理与隔离期限；
- 各语言真实命令和所需服务。
