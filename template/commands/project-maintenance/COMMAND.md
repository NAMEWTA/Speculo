# 项目维护

区分用户要审计、实际修订、提纯知识还是归档；明确要求的组合可以一并完成。仅要求审计时返回发现，要求修复时执行该范围，不重复索取已经给出的授权。

## 文档修订

用当前代码、配置、可用命令和产物核对 README、架构、使用指南和项目入口。修正失效路径、过时行为和缺失说明；变更记录描述版本事实，项目入口只保留发现和工作所需的信息。

合并重复说明时保留专业内容与必要例子，让旧入口能找到新事实。删除材料前辨明唯一来源、历史证据和仍在使用的资料，不以字数或文件数作为清理目标。

## 知识与归档

将未来仍会影响行动的决定、背景、设计和已验证故障经验更新到已有位置，按 [持久化](../../references/memory.md) 处理。软件交付可用 [archive-and-consolidate](../../workflows/specdev/specdev-a-archive-and-consolidate/SKILL.md)，学习主题可用 [consolidate](../../workflows/learning/learning-c-consolidate/SKILL.md) 与 [archive](../../workflows/learning/learning-a-archive/SKILL.md)。

当前事实整理完成后再归档依赖它的结束记录；保留未解决事项和历史采用的版本，检查移动后的引用。当前设计、部署方法和活跃知识继续在长期位置维护。

## 写入与核对

保留无关编辑和用户材料，冲突只阻塞相关目标。安装器的锁、事务、备份和归属元数据由其恢复入口处理，普通文档整理不接管它们。

报告实际修改、核对结果和未处理事项；原记录足够时不另建总报告或游标。提交、推送和远端写入只完成当前请求覆盖的范围；无实质变化就说明无变更，不制造提交。
