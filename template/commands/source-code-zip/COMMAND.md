# 源码与工程 ZIP

确定用户需要的是源码阅读包还是可复建工程包，以及源目录/提交和输出位置。已有明确范围直接使用；未说明复建用途时可采用内置工具的源码阅读包行为，并如实说明内容。

## 源码阅读包

使用本命令的 [独立 Node 工具](scripts/zip_source_code.cjs)，不需要安装依赖。定位已安装命令目录中的脚本，源目录和输出路径分别解析，避免依赖当前 cwd。

```bash
node /absolute/path/zip_source_code.cjs /absolute/source --dry-run --verbose
node /absolute/path/zip_source_code.cjs /absolute/source --output /absolute/output/source.zip
```

工具保持既有默认过滤：源码白名单、跳过依赖/构建产物/秘密文件/链接，并排除 YAML、锁文件、普通 JSON、文档和媒体。它适合阅读源码，不承诺完整复建。需要额外未被忽略的文件可以 `--include`；更多参数见 [工具参考](references/cli-reference.md)。

## 完整工程或指定 Git 版本

需要完整工程时，先列出源码、配置样例、锁文件、构建脚本、文档及必要资源。使用适合该范围的 Git 或现有归档工具，保留明确需要的文件。不要把内置源码过滤结果误称为完整工程；不为加入 YAML 或锁文件就无检查地关闭所有秘密排除。

指定提交使用固定 SHA。工作区打包另外核对未追踪文件、子模块和符号链接；不跟随链接把范围外目录带入。输出放在候选文件集合之外，保留已有同名文件，只有用户要求覆盖时覆盖。

## 核对与交付

生成前核对实际候选清单，尤其是真实凭据与项目必需文件。生成后读取 ZIP 清单、抽查关键内容，确认可以打开、目录结构正确、内容对应本次约定版本。

交付真实路径、采用的版本/工作区、文件数量与主要排除项。说明复建限制和未打包材料；预览结果不称为 ZIP。需要跨会话保存时按 [持久化](../../references/memory.md) 放入既有交付位置，不另建命令状态协议。
