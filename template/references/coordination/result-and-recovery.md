# 结果核验与恢复

返回方式按 session-files.md 的实际恢复需求选择；即时只读结果从真实工具调用关联，持久交接从冻结 TASK/REPORT 回读。无文件不代表没执行，结构化返回也不代表已验收。


接收任何领域的派遣结果或恢复中断任务时读取。Lead 核验实际产物、协调原 owner/gateway 更新正式状态并最终回复。

## 接收

1. 从实际存在的原计划、任务输入、业务工件或当前审查输入找到任务、实际 Work、工作区、基线、owner 和工具句柄；没有业务对象时不补造对象；确需持久交接才使用全局派遣目录。有文件交接时按 <Path>{roots.references}/coordination/session-files.md</Path> 回读 TASK 与 REPORT；即时结果核对 call/task；持久交接回收运行交接校验器的 return 阶段，核对 session/task、实际工具尝试和候选身份，先看聚焦交接。需要回查历史时，仅当 REPORT 有 `Session log` 行且该地址可读、属于本任务时，再结合 TASK 内容检索少量片段。返回必须对应同一目标；过时结果保留为历史材料，不能覆盖当前决定。
2. 通过当前工具指南核对任务是否确实返回，以及是否仍可能继续写入。已接收、已开始、会话空闲、任务结束、进程退出和业务通过分别记录；结果不明先查询，不重复发起任务。
3. 检查实际产物、版本和允许路径；涉及 Git 时核对基线、可达 checkpoint、tip、dirty 状态及 tracked/untracked/ignored 变更。返回文本不能替代真实候选。
4. 按原验收合同核对检查及输出。执行者修改测试、配置或验收脚本时，判断是否改变了通过标准，不接受伪绿色结果。自报、模拟、截图和推断在 Lead 核实前保持未验证。
5. 对照任务验收核对计划、文档、代码、说明、findings、来源或检查观察。独立审查的身份与资格由原领域合同决定，不能通过改名、换会话或自报绕过。Worker 已直接写入的文档仍是待验收产物，不能据此提前推进状态。

即时返回或 REPORT 的 completed 只表示候选已交回；blocked、failed、cancelled 分别按报告事实处理，均不能直接覆盖原业务状态。Lead 通过原 owner 在当前负责工件保存实际返回引用与 Lead 验收；不改写冻结 TASK 或 REPORT，不在 Evidence 复制日志地址，也不另建交接文件。既有历史报告按原合同保留。缺身份、状态或可核验产物时只阻塞本次验收。持久交接已提交报告的修正/重试创建新派遣目录并引用旧结果，业务上仍属于原任务，不为重试制造业务对象。

## 修复与集成

同范围 finding 有明确修复路径时继续原任务修复和复验，不逐项询问、不为每个 finding 新建对象。复用已选工作区，冻结新的实际输入；提交、合并和外部动作继续核对原授权，不创建额外 worktree。

达到 owning Work 的有效尝试上限或重复相同 blocker 时，在当前负责工件记录共同失败模式、最可能原因、下一轮具体改变、下一 owner/路由。只有有实质变化和新证据才开始下一尝试。更换执行者、清空 attempts 或再次询问相同问题不构成变化。

## 中断恢复

- 读取原任务输入、实际存在的计划与负责工件、最近验收和实际候选，核对当前版本、输入与真实 Work 是否漂移。
- 使用原调用真实返回的工具句柄查询原任务；缺少 `Session log` 行或 REPORT 不能推断没有执行。突然中断而无报告时，由 Lead 在原负责工件记录已知/未知事实与恢复入口，不伪造执行者成功报告；临时文件不算完成回报，也不能留在任务目录。
- 仍可能写入或副作用结果未知时，不让 Lead 或另一执行者抢写；按当前工具指南检查、等待或在原授权下取消。
- 当前会话不具备查询能力时，说明缺失事实和恢复入口，不伪造停止证明。
- 原历史记录不可读时在负责工件说明缺失，使用报告与真实产物核验；只有缺失事实影响验收时才阻塞对应部分。回查历史不隐式恢复旧会话或授权再次执行。
- 用户改变后续偏好时在下一安全阶段采用；撤销权限立即停止新动作并处理进行中的任务。
- 独立且已授权的其他 eligible 节点 可以继续；仅阻塞冲突任务及其依赖闭包。

## 外部网页返回

external-web 按 <Path>{roots.references}/coordination/exchange/source-package.md</Path> 使用临时压缩包传输。在任务目录之外检查路径穿越、绝对路径、符号链接、重复或大小写冲突、异常膨胀和嵌套归档；不直接解压到工作区或交接目录，不直接执行返回脚本。将候选与预期 checkpoint 比较，Lead 在选定 workspace 应用获准变更并完成本地验证，再把结论写入 REPORT。传输包、下载和解压结果在处理完后立即删除。输入或授权改变时建立新 task；不覆盖旧 TASK 或 REPORT。

## 完成

每项通过结论必须有可回读事实。Lead 核验后通过原 owner/gateway 更新负责工件和正式状态，继续已授权且前置满足的任务，最终核对用户要求的整体交付。完成不自动获得提交、发布、部署或清理授权；会话 handoff 只在用户明确请求时执行。
