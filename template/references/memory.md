# 持久化

需要保存成果、接续工作或更新长期知识时才读本文件。目标是让下一次工作少猜测，不是留下整个执行过程。

## 位置与内容

优先使用用户指定或项目已有的位置，引用现有代码、配置、文档和设计，不复制第二份。无既有约定时，以项目根下 `.agents/speculo/.speculo/` 保存工作资料。

| 按需使用的位置 | 内容 |
| --- | --- |
| `releases/<name>/README.md` | 一次软件交付的来源、范围、决定、进度、实际检查与交付结果 |
| `knowledge/adr/` | 跨交付仍有价值的重要决定、真实替代方案及取舍 |
| `knowledge/context/` | 代码和配置不能直接表达的业务背景、约束与项目事实 |
| `knowledge/error/` | 值得防止重演的问题、证据、已验证原因、修复与预防方法 |
| `knowledge/design/` | 当前有效设计及必要候选，允许代码、HTML、样式和图像 |
| `environments/<name>.md` | 可复用部署目标、数据位置、发布入口、健康检查与恢复方式 |
| `archive/<name>/` | 已结束交付的历史记录，保留当时采用的设计版本与结果 |

这些位置是建议，不要求预先创建。学习、创作和咨询使用各自入口的简单位置；临时分析放临时目录，不混入当前知识。

默认一份记录就够：目标与来源、关键决定、已完成和剩余事项、实际证据。按内容需要选标题，无需空章节、表单、固定字段或配套状态文件。

## 提纯和更新

只有未来还可能影响行动的内容才进入长期知识。普通局部修改不需要 ADR，尚未验证的推测不能写成已知原因或通用经验。

先找已有记录，更新当前事实；重要决定反转时保留原理由并链接新决定。历史执行细节留在交付记录、提交或日志中，不追加到每份知识文档。

记录来源和适用条件。涉及验收或可变外部材料时，保留当时的固定版本、提交或必要快照；没有证据的部分明确标注未知。

每个事实保持一个主要维护位置。图示、代码或可运行原型已经说明问题时，补充必要上下文即可，不必再写等价 Markdown。

## 引用与归档

路径用项目根相对位置并说明基准；跨目录移动的记录优先用这种定位或固定提交链接。文件内部资源用随目录一起移动的相对链接，避免依赖原父目录层级。

设计候选、已确认版本和当前实现分别说明。更新当前设计时保留历史验收指向的版本；新结果不覆盖原始回答、观察或已经确认的历史证据。

归档前补齐真实结果和未解决事项，提纯仍有效的知识，再检查移动后的引用。归档是历史，当前规范和可执行操作说明从活动位置读取。

无需长期价值的临时草稿可按任务范围清理，保留唯一来源、用户材料与有用的未完成工作。名称冲突先辨明对象，不覆盖另一项任务。

## 写入和恢复

沿用用户已经授权的任务范围。先读现有内容，保留无关编辑；遇到同时修改或事实冲突时只解决相关部分，不接管整个目录。

写完回读结果和必要链接。中断后核对文件、Git 或实际系统状态再接续；文档里的完成描述不替代真实验证。

秘密值保存在既有凭据管理处，说明中只留引用。记录能帮助恢复的信息，不收集与任务无关的敏感数据。
