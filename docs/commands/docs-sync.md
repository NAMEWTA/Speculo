# Docs Sync：让项目文档反映当前事实

[手册首页](../README.md) · [Command 目录](README.md) · [源入口](../../template/commands/docs-sync/COMMAND.md)

**业务 ID：** `command/docs-sync`

## 什么时候用

项目文档长期未整理、README 与实现不一致、文档分散，或者你明确想盘点 AGENTS、项目 Skills 和指令资源。普通实现会维护本次相关文档，不会自动触发这个全局命令。

## 选择模式

| 模式 | 适用请求 | 会做什么 |
|---|---|---|
| `audit`（默认） | 先检查问题 | 全局盘点与会话报告，零文件/Git/state 写入 |
| `update` | 整理或修改文档 | 更新授权范围，可选保存新报告；不暂存或提交 |
| `commit` | 明确提交本次文档整理 | 更新并只提交获批目标及必要报告/state |

```text
明确调用 command/docs-sync，mode=update。
全面核对 README 与 docs，让它们只描述当前产品、安装和使用方式，
把过时开发迭代报告从用户文档中移除，修复导航；本次不提交 Git。
```

## 输入和处理过程

提供项目目录、目标文档范围、希望保留的内容和模式。AI 从真实代码、配置、入口与调用方核对事实，对盘点中的目标逐项给出保留、更新、合并、删除或阻塞结论。Git diff 是线索，不把盘点范围限制为最近改过的文件。

整文件删除、受保护知识和范围外修改需要相应授权；已经覆盖具体范围的批准会复用。没有 workspace 只阻塞依赖 runtime 的写入，独立审计和获准项目文档编辑仍能继续。

## 产物与完成

update 返回实际修改、链接/事实核对与 `not-committed`；audit 返回发现；无实质变化可返回 `no-op`。需要保存的报告属于 `roots.state/commands/docs-sync/`，不写进方法定义目录。

只有 commit 分支维护命令同步状态和相应 sidecar。提交不授权 push、tag、stash、清理或历史改写；无关暂存内容必须保持。项目产品 docs 应保留现行手册，而不是本命令每次运行的流水记录。
