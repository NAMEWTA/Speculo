# Handoff：让另一个会话接得上

[手册首页](../README.md) · [Command 目录](README.md) · [源入口](../../template/commands/handoff/COMMAND.md)

**业务 ID：** `command/handoff`

## 什么时候用

上下文快满、要换 AI/会话、准备暂停较长时间，或者想把当前范围交给另一位执行者。它生成一个紧凑恢复入口，不复制整套规格和所有聊天。

开头用三至五句话做聚焦交接，说明完成内容、关键决定、停点和下一步。有[外部派遣报告](../agent-handoffs.md)时引用原报告，不再复制正文。

## 怎样调用

```text
明确调用 command/handoff，为下一个会话保存当前任务交接。
重点写清已完成内容、实际检查点、未闭合动作、授权范围和下一安全步骤。
```

输入是当前任务范围与已经存在的真实材料；可以补充“下一会话重点排查某个失败测试”。

## 文档应该包含什么

| 内容 | 接收方要能确定什么 |
|---|---|
| 目标与边界 | 交付数量、已接受决定、不可放宽约束 |
| 检查点 | change/Ticket/Run、owner、branch/worktree、HEAD 或摘要 |
| 权威指针 | 规格、计划、Evidence 和建议调用的真实 Skill |
| 未闭合动作 | 哪些结果未知、原授权和回执在哪里 |
| 下一安全动作 | 一个具体动作及进入、验证和停止条件 |
| 历史回查 | 工具、所属主机、真实会话 ID 与原记录 locator、核验者和核验主机、会话对应关系及可读性、本任务范围与检索关键词；未核验或缺失时说明 |

路径使用项目根相对路径，敏感值不进入交接。报告保存在 `roots.state/commands/handoff/` 的带日期、scope、topic 文件中，冲突时递增编号，不覆盖已有报告。

提供历史入口前，主动从当前工具元数据或历史接口定位并核验，不能猜缓存路径或取“最新日志”。原记录使用“所属主机＋工具原生绝对路径”或工具原生历史入口作只读定位信息。默认不复制聊天；确需长期保留或接收方无法读取时，引用现成派遣快照，或由本命令保存报告相邻的同名 `.history-01.jsonl` 等附件，注明来源、捕获时间与完整/节选范围。不会为此新建 change 或 session。

## 新会话如何继续

```text
请先读取这份 handoff 的实际项目相对路径，核对 roots、owner、当前 HEAD 和未闭合动作，
再从它列出的下一安全步骤继续。发现漂移时报告受影响范围。
```

交接文字中的“已批准”不是新授权。远程超时要查询原 marker/目标，OPS 失败要恢复原 Run；不能把交接理解成可以删锁、重放迁移或重复发布。

先读摘要和当前业务工件，有具体疑问才确认记录主机与本端访问能力，按关键词及本任务范围检索少量历史片段。JSONL 按工具实际格式读取。回查原会话不等于 resume 原进程，历史说法与当前文件不一致时核对真实状态。
