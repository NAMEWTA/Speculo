# Learning：课程、探究与学习积累

Learning 保留九项学习能力。领域入口用于判断当前是在学新内容、深入问题、练习、复习还是整理知识；这些能力不要求按照固定课程状态机使用。见 [Learning SKILL](../../template/workflows/learning/SKILL.md)。

## 建立适合当前学习者的路径

`init-setup` 了解已有知识、实际目标、时间和偏好，有可复用信息才保存。`assess-and-plan` 找出会影响理解的先修缺口，并组织适合目标的课程。已知背景直接沿用，不能把每次问答都变成入学测试。

`goal` 面向“学会做某事”的长期目标，连接知识、练习和可观察结果。例如“能独立排查 PostgreSQL 慢查询”应落到读执行计划、分析数据分布和验证索引等能力；规划深度由实际学习跨度决定，不创建 Agent 调度或固定学习轮次。

## 完整讲课与问题探索

`lesson` 用连贯讲解建立概念、直觉、必要推导和真实例子，并说明类比的适用边界。用户要完整一课时给完整内容；用户要短答时控制范围，不能用一串问题代替应有的讲解。

`question` 支持直接深挖和互动式探究。直接深挖围绕证据、假设、机制与反例展开；苏格拉底或费曼式练习根据用户明确选择进行。真实回答作为反馈，不能替学习者作答后宣布掌握。

使用外部资料或代码时区分来源结论与自己的解释。动态技术事实查当前官方资料，历史材料保留其版本与语境。

## 练习与复习

`homework` 提供能检验目标能力的练习，评阅真实提交并解释错误原因。练习数量、难度和反馈粒度随学习目标调整，不预设每课必须答几题。示例答案和用户答案明确区分。

`review` 关注延迟保持和迁移，适合通过回忆、解释、应用或新的情境检查理解。历史一次正确不自动代表长期掌握；同一个错误反复出现时调整解释和练习方式。

例如学完索引后，复习可以让学习者解释一个未见过的查询为何没走索引，并用观测验证，而不是只复述定义。

## 形成长期学习资料

`consolidate` 将多次课程、问题和练习中的有效结论整合到已有主题位置，保留来源、适用条件、尚存分歧和真实薄弱点。不要把一段未经核验的回答直接提升成通用结论。

`archive` 保存已结束学习项目的历史，把仍会复用的知识和未来复习入口留在活动位置。原始回答、反馈与引用保留其身份；临时推演不需要全部永久保存。

默认沿用项目已有笔记结构。有接续价值时保留一份主题记录即可，不强制 learner-profile、question-map、状态 JSON、IQ 提交口令或课时表单。位置与更新原则见 [持久化](../../template/references/memory.md)。

## 使用例子

> 用 Learning 完整讲一课数据库事务。我懂基本 SQL，但没学过隔离级别；请用一个并发转账例子串起来。

> 用 learning/question 深挖这段代码为什么产生死锁，直接分析，不用先考我。

> 用 learning/review 检查我一周前学的索引知识，给我一个新的查询情境，根据我的实际回答反馈。
