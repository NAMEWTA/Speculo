# Media：创作、视频与发布草稿

Media 保留七项创作能力。入口见 [Media SKILL](../../template/workflows/media/SKILL.md)，每个 Work 都可以独立使用。作品、参考分析、工具执行和传播效果分别以真实材料为依据。

## 需求与参考

`init-setup` 了解品牌、受众、渠道、已有素材和制作环境；有长期价值的信息保存在项目的创作资料中。`brief` 将模糊选题整理成受众问题、核心主张、证据、表达形式和约束。已有明确简报无需重复访谈。

`deconstruct` 分析用户给出的作品或实际读取的参考：开场怎样建立期待、信息怎样推进、画面与文字怎样配合、哪些机制适合当前受众。无法访问原作品时说明依据范围，不把标题推断写成内容分析。

借鉴结构和表达机制时保留自己作品的事实与定位，不直接搬运他人受保护的完整作品。

## 手绘与图像方向

`hand-drawn` 保留按需查阅的风格知识，默认交付明确、可复用的图像提示词。用户指定具体上游配方时沿用其特征；自定义创作则说明参考角色与实际取舍，不能把自由改写称为精确复现。

提示词应说清主体、构图、材质/笔触、文字与用途。只有用户请求生成且当前工具可用时才产生实际图像；文本提示词和已生成图片分别交付。

## 视频工程与真实渲染

`video` 从受众与表达目标组织脚本、镜头、时序和声音关系。工程可以是 HTML 等代码形式。配套独立渲染工具保留真实截图与 MP4 输出能力，使用普通技术参数，不要求先填 brief/shot/review 状态 JSON。

先确认项目已有渲染方案，优先复用。只有实际执行并检查输出后才能说视频已生成；没有浏览器、ffmpeg 或音频资源时，交付当前工程和具体缺口。时长、帧率、尺寸、音画关系与关键时点要按作品实际需求核对。

离线示例和工具参数位于 [视频 Work](../../template/workflows/media/media-v-video/SKILL.md) 的资源中。运行示例证明工具能产生文件，不证明视频的传播效果或所有浏览器布局都相同。

## 发布草稿与效果复盘

`publish-draft` 将已经确定的内容转换为目标渠道可使用的本地标题、正文、封面、资源及必要说明。平台规则需要当前依据。草稿导出完成不等于已线上发布；用户要求发布时核对实际接口、账号和范围，并读回结果。

`retro` 根据真实发布数据、用户反馈或作品审查找改善方向。没有实际指标时可以做作品复盘，但不能编造曝光、转化或因果关系。把验证过且可复用的创作原则更新到已有位置。

## 持久化与接续

优先保留作品本体、简短创作记录和有用来源。脚本、HTML、图片、视频、字幕和音频可以直接作为资料，说明文字补充它们无法表达的决定。没有必要再维护一套固定 JSON 状态与自评分表。

> 用 media/deconstruct 分析这段广告的开头和信息节奏，再提出适合我们产品的脚本方向。

> 用 media/video 把这个已确认脚本做成 10 秒演示，输出工程和实际渲染文件；保留以后修改文案的位置。

> 用 media/publish-draft 把同一主张整理成微信公众号与短视频简介的本地草稿。
